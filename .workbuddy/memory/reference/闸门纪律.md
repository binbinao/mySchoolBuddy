> **加闸门时必问**：这条事实**从哪来**？谁查过它的**源头**？**页面比数据层多出信息，本身就是一条告警信号。**
> 已确认成员（别指望是最后四个）：`answerKey`/`childAnswer`·`stem`/`breakdown`/`breakdownKey`·`doneRight`/`doneWrong`·`cause*`·`full`/`lost`。**下一个候选：④ 段 `variants` 与 ⑤ 段 `thinkQuestions` 的内容正确性**（只查了配比与结构，题目本身对不对没人查）。

**新数据入口检查清单**（加一个入口必须同时问）：① 结构/必填 ② 枚举合法性 ③ 溯源存在性 ④ **页面级对应** ⑤ **副本/派生** ⑥ **回退法自证（正反两面）** ⑦ **事实源头**——原始事实还是从别的字段推出来的 ⑧ **字段是否真的存在**。前 12 轮漏的几乎都是 ④⑤⑥。

**铁律（每条的踩坑实例见 automations 记忆）**：

1. **「0 错误」可能只是没检查到。** 改完校验器要看它有没有立刻抓出存量违规——**抓不出才说明检查没生效**。**字段名错了等于没校验。**
2. **闸门必须覆盖它声称覆盖的全部数据入口。** 当前 6 个：`raw-manifest`·`wrong`·`exams`·`tasks`·`resources`·`data/README.md`，外加 `docs/*.md` 与错题精讲页。命名/注释必须写明覆盖范围。
3. **上线前先跑一次看它报什么——自身假阳性会把真错误淹掉。** 六类复发：`startswith` 让「I」命中「III」· 哨兵值当枚举外值 · **把「尚未定论」误判成「已定论」** · 按错误分隔符拆内容（`<br>` 不是换行）· 判据太严（比**事实标记**而非整句字面）· 判据前提是「违规内容本不具备的性质」（恒假＝免死金牌）。
4. **「查了数据层」不等于「查了整个事实链」。** 内嵌数据必须逐字节比对，**修复要用数据层重新生成**；**同一事实散落 N 处，按「事实」建闸门不是按「文件」建闸门。**
5. **规范文档是数据入口的一部分，而且最危险。** 按**结构**判定而非关键词全文匹配，且**文档要写明机器管不到什么**。
6. **闸门自身的漏洞比没建闸门更危险**——会报「0 错误」让人以为安全。**只有回退法能暴露，正反两面都要验**（认不出来的东西要**报错**而不是放过）。⚠️ 回退法本身会出事：用 `git checkout` 还原测试文件会抹掉同文件里的合法修复——**先 `cp` 备份、还原后逐字节比对 sha256**。⚠️ 用例也会设计错（第 16 轮把真实缺陷当合法样例）。**闸门报错时先怀疑用例，别急着调阈值。**
7. **修掉一个实例不等于修掉这一类**——纪律要落成**可自动判定的闸门**。
8. **派生量不手写**：每个写入方都要现算。「本次运行」概念的数据（增量、unchanged）根本不该落盘。
9. **`docs/*.md` 是第五个漂移面**：只审能自动判定的事实，不做全文数字正则扫描（11 条里 9 条假阳性）。**覆盖广但靠关键词打补丁的闸门，不如按定义能自动判定的窄口径。**

### done ≠ 做完了

`status: done` 只说明**上一轮自认为**做完了。**即使 `pending: 0` 也不要直接收工**，先 grep `待补 ·`（带间隔号，页头「分值待补」标签是合法状态标记）确认真空缺。**判据是页面内容，不是队列状态。**

十六轮踩了五种「假 done」：① HTML 有空缺 → ② HTML 齐了但 JSON 空（grep HTML 查不到）→ ③ 两侧都有内容但「对不对」没人查 → ④ 源头事实无闸门 → ⑤ **数据层根本没有承载该事实的字段**。
**交付错题内容是三处动作**：① 填 HTML 空缺段；② **回写 `data/` 同名字段**（先确认字段存在，不存在就是第 ⑤ 类）；③ 两侧符合五段范式。

## 判据设计的四次打回（本轮实录）

| 版 | 判据 | 结果 |
|---|---|---|
| v1 | `"真题" not in ev` | **6 条 tier1 全误伤**——实际写的是「2025 中考第 N 题」 |
| v2 | 扫全部中文字面量 | 误伤 `chk_tier_ordering` 的**报错文案**（不会被渲染） |
| v3 | 只扫 `para()` 实参 | **回退法自证失败**：注入违规仍报 0 错误（文案在列表字面量里） |
| v4 | 按函数体屏蔽 `def chk_*` | ✅ 正反两面都验证通过 |

**三条可复用的结论**：
1. **字面锚点必须选真实存在的东西**，不能选自己以为在的词（「真题」）。
2. **判据收紧到窄口径后必须再跑一次回退法**——v3 就是靠回退法抓出来的，
   而「闸门全绿」当时看起来是成功信号。
3. **排除项要按「语义边界」切（函数体/文档区），不要按「写法相似」猜**。
   判据前提若是「违规内容本不具备的性质」，就是恒假＝免死金牌（铁律 3 第六类复发）。

## 派生量 `count` 的两处不一致（本轮踩到）

① `meta.count` 手写 ⇒ 与实际条数不符（封面说 29 条、翻完 28 条）。
② `evidence_sources` 里写「`RAW/试卷库/`（5 套…）」**带括号描述**，
`os.path.exists` 整串判 False ⇒ **每次必报「出处指向空气」**，而路径其实是对的。
⇒ 判据要**取括号/书名号前的路径前缀**再判存在性。
**修法顺序：先怀疑判据（放宽取前缀），再改数据（补斜杠）——反过来就会把真错误放过。**
