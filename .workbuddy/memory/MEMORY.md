# mySchoolBuddy · 项目约定

## 交付标准

**讲题类内容一律出单文件 HTML，不要用聊天文字讲题。**（2026-10-02 用户反馈："文字讲题是我看得清，不是他看得清"。孩子的认知负荷要靠分层/渐进/图形/可交互降低。）

### 五段范式（硬性标准，已落成机器闸门 `check_five_stage_paradigm()`）

「练一题，看三题，想五题」：① 原题 → ② 拆解 → ③ 零跳跃讲解 → ④ 三题变式 → ⑤ 迁移想五题。skill `wrong-question-coaching`。

| 段 | 硬性要求 |
|---|---|
| ① 原题 | **置顶**。题干**逐字**全文（见「题干拆解字段」）+ 限定词 `<span class="hl">` + 原卷照片（题干裁切+整题，折叠）+ 题干拆解表 |
| ② 拆解 | 表格逐句翻译成条件，**收尾点明「最容易漏的是第几条」** |
| ③ 零跳跃 | 一步一个动作，★ 标断点，**每步三件套：动作/依据/检验**。末尾逐个原始条件验证 |
| ④ 三题变式 | **固定配比**：简单变式（只改一个数值）+ 同类型（换考点同手法）+ **问答对调**。答案全 `<details>` |
| ⑤ 想五题 | 3-5 递进问题，填空+即时判题，**末题必为「什么情况下这方法失效」** |

总时长 25-35 分钟。**问答对调不可省**——很多孩子是「记住套路」不是「真懂」。**文科适配**（语/英/史/政/地）：骨架不变。②标注答案在第几段+材料层次；③逐句解读文本（定义句/条件句/答案句/干扰句）；④换材料换设问（概括→原因→评价→启示）；⑤题型识别+答题角度转换。

### 单文件 HTML 规格

单 `.html`，内联 CSS/JS，零外部依赖 · 正文 max-width 780px · 浅色 Stripe + 钛金灰 `#1C1C1E`/`#A1A1AA` + 暖金 `#F59E0B` · 16px 基准（移动端 15.5px）/行高 1.75/断点 600px · 命名 `docs/实战表/学科/题号-主题-精讲.html` · 模板 `skills/wrong-question-coaching/assets/template.html`。

**图像**：原图存 `RAW/`（已入 Git，事实依据层）。**页面必须引 `RAW/`，不要引 `data/_scans/`**（gitignore + 含个人信息，远端必断链）。**交付前必须用真实浏览器验证 `img.naturalWidth > 0`**。

**必备结构**：图形先行 → 已做对的部分 → 断点定位 → 分步法 → 坑的形态对照表 → 检验题 2 道（答案折叠，用户讨厌剧透）→ 复述检验 → 家长区（深色卡片，具体到分钟）。
**交互**：渐进解锁 · `localStorage`（key `msb.<题目>.progress.v1`）· 即时判题（关键词宽松匹配，答错只提示不给答案）· `<details>` · 复制按钮 · 重置需 `confirm`。

## 数据纪律

### 错因判定

**仅凭最终答案判错因会误判，必须回看中间步骤。** 2026-10-02 q19：最终答案错但中间方程全对——只看答案会误判成「概念不清」，回看步骤才是「方法没想到」。**二者救法完全相反**，混淆=无效刷题。录入错题必须附中间步骤判读。

### 分值

**照片上没有分值标注就留 `null` + `scorePending: true`，绝不估算。**

- **反向同样成立**：卷面明确印了单题分值（V-D「第 57-60 题每题 2 分」）**必须回填**，留 null 是失职。判据是「照片上有没有」，不是「推算得出来吗」。
- **算不出合计就不给合计**。分项有一处不明就别写「已确认实得 X 分」——无依据的合计会被当结论引用。**模块/全卷 `got` 同样可为 null**，须配 `gotNote` 写明为何不折算；**含 `uncertain` 题的模块 got 必须为 null**。
- **⚠️ 这是「一类」不是「一例」**：别问「哪个模块要留空」，要问「**这个数有没有卷面依据**」。闸门 `check_module_got_grounded()` 按可自动判定口径覆盖，不靠人记模块名。**规范源 = `data/README.md`「分值纪律」章节**（闸门 `check_data_readme`）——曾写「full/lost 必填」，与纪律完全相反，照它录数据会诱导估算。

### cause 字段

**只能是五类枚举之一**（概念不清/方法没想到/计算失误/审题错误/表达不规范），长描述放 `causeNote`，副因放 `causeSecondary`，**只选一个主因**。存疑用 `causePending: true`，不硬归类。

错因五类在仓库有 **7 处定义**，靠人记必分叉。**定义源 `docs/方法论/错因分类与复习排期.md`**，其余六处逐字一致：`validate_schema.py:CAUSES` · `app/index.html:#w-cause` · `#f-cause` · **`const ci`（chip 着色，缺项静默退化成灰 `c0`）** · `README.md` 示例 · `build_skeletons.py:CAUSE_TONE`。机器比对 `check_cause_enum()`。**第五类是「表达不规范」不是「时间不够」**——后者是条件不是病因（做不完的真因通常是「卡壳不会跳过」，归 `方法没想到`，救法加限时套卷）。

### 答案字段（第十四轮：事实源头之一）

`childAnswer` 决定「已做对的部分」能写什么、`answerKey` 决定「断点在哪」才成立。**答案错了整套教学判断全部反着走，而孩子会照着错答案继续练**——比分值估错严重得多。

规范拼写只有两个，不接受别名：`answerKey`（正确答案，必填；反推的必配 `answerKeySource`）、`childAnswer`（孩子原答案，必填，原样保留批注痕迹）。已清存量：`correctAnswer`（全站零读取方）、`myAnswer`（生成器曾用 `childAnswer or myAnswer` 兜底 ⇒ 改错那个会静默生效）、`stemHtml`（数据层根本不存在的键）。**`or` 兜底链是拼写分裂的温床**——一个键不能有两个意思。

**⚠️ 机器守结构，守不住语义**：把第 11 题 `answerKey` 改成 `give up smoking`，校验器**不报错**——英语/语文答案是自由文本。**这是能力边界不是漏洞。** 「答案正确」只能靠核卷与人工复算。

### 题干拆解字段（第十五轮：14 类家族的第二个成员）

`stem`（逐字全文，括号补充与问法一字不省）· `breakdown`（`[[题干原句, 翻译成条件]]`，**左边必须是原句不是概括**）· `breakdownKey`（收尾点明「最容易漏的是第 N 条」，N 须在 `1..len(breakdown)` 内）· 页面「题干拆成 N 个已知」的 N = `len(breakdown)`。

闸门 `check_breakdown_faithful()` 管：结构（每行二元组无空格）· `breakdownKey` 引用完整性（**只在「第 N 条」语法位置取条号**，否则说明文里的 d=6 被误当条号）· 页数一致 · 页面首列每行能在数据层找到原句。**不管**：翻译讲得对不对、首列与题干是否语义等价——**两侧一致 ≠ 两侧都对**（第十五轮正是靠核卷才发现页面题干把双向条件篡改成单向）。

### 核卷

**判分前必须放大原卷，不能看缩略图。误判比漏判更危险。**
`sips -c 高 宽 --cropOffset y x x.jpg --out /tmp/x.jpg` 裁切 → `sips -Z 2000 /tmp/x.jpg --out /tmp/x-big.jpg` 放大。

四次教训：① 红笔 × 可能是划干扰项不是判错（第 46 题）。② **一条长斜线 ≠ 逐题批改**（须追踪笔画走向）。③ **只标大题总分 ≠ 可折算**（III 印「8 分」共 8 空、IV 印「10 分」共 5 空，均无单空分值）。④ 页面题干把双向条件写成单向，**只有放大逐字读才看得出来**——缩略图上完全正常。

### 跨层一致性

**同一事实在数据层与所有页面必须一致。打架时不选边站，回原卷裁决。**

> **裁决原则**：找出「**两边都缺依据**的那个共同前提」，显式记成 null。

实例（第五轮）：听力模块 `got=25`（满分）却在同一行 evidence 写「11 仅错 1 空」且 wrongs 里有第 11 题，两页又分别写 25/25 与 24/25。裁决：卷面只标「10 分」共 5 空、无单空分值 ⇒ 两个数**都是等分折算，都不能用** → `got` 改 null + `gotNote`。第十二轮复发（跨页写 9/10、题数 23 当满分）。

### ⚠️ 闸门纪律（九条）

已连犯**十五类「0 错误也抓不到」的缺陷**，此处只留**形态**（题号/改法见 automation 记录与闸门 docstring）。**新增缺陷请归入某一形态，不要新增行**——这张表的价值在于收敛：

| 形态 | 为什么抓不到 |
|---|---|
| 漏字段 / 漏入口 / 把错误藏起来 | 单看任一处都「像对的」；字段名写错 ⇒ 报错读不出定位信息（「第?题」），等于没查 |
| 检查本身抓不到 | 「HTML 齐了 JSON 空」按定义 grep HTML 查不到；「修掉一个实例」会被「已处理过了」锚定 |
| 副本漂移 / 静默失效 | 闸门读「磁盘 JSON」，漂移发生在「拷进 HTML 之后」；散文数字既不在 JSON 也不在 `const` 块；同概念两套拼写——每种写法各自自洽，页面照常渲染 |
| 规范反了 | 只查「数据对不对」，从没查「教人写数据的文档对不对」 |
| **源头无闸门**（14 `answerKey`·15 `stem`/`breakdown`） | 闸门围着**派生量**建，**没一道查过推导它们的原始事实**——源错了派生量一致地错，于是每道都显示「通过」 |
| 内容无闸门（13） | 页面级闸门只审 exams 侧；精讲页是唯一承载教学判断的产物，却只被查过「非空」 |

> **可复用结论（加闸门时必问）**：这条事实**从哪来**？谁查过它的**源头**？
> 成员清单：`answerKey`/`childAnswer`（14）· `stem`/`breakdown`/`breakdownKey`（15）· `cause`（枚举）· `full`/`lost`（分值）。**下一个候选：`doneRight`（已做对的部分）——它逐项引述孩子的手写过程，与 `childAnswer` 同级，至今无人查。**

逐轮细节见 `.workbuddy/memory/automations/3480cd21-*/memory.md`。可复用要点：

- **新数据入口检查清单**（加一个入口必须同时问）：① 结构/必填 ② 枚举合法性 ③ 溯源存在性 ④ **页面级对应** ⑤ **副本/派生**（内嵌块、文档、派生列表）⑥ **回退法自证（正反两面）** ⑦ **事实源头**——这个字段是「原始事实」还是「从别的字段推出来的」。前 12 轮漏的几乎都是 ④⑤⑥。
- **拼写分裂**：两个脚本写同一个 JSON、页面读错拼那个 ⇒ 新条目同时失去徽章/筛选/统计，**页面不报错、卡片照常渲染**。凡两个脚本写同一文件先核对键名。
- **`docs/*.md` 是第五个漂移面**：结构化闸门覆盖不到。**只审能自动判定的事实，不做全文数字正则扫描**（那样 11 条里 9 条假阳性）。**覆盖广但靠关键词打补丁的闸门，不如按定义能自动判定的窄口径。**
- **派生量不手写**：采集脚本**每个写入方都要现算**，只修数据层＝把漂移推迟到下次采集。**「本次运行」概念的数据（增量、unchanged）根本不该落盘。**
- **范围确认**：`app/index.html` 用 localStorage、不读 `data/*.json`、设计如此，**不算漏网入口**。

**九条铁律**：

1. **「0 错误」可能只是没检查到。** 判据是「该数据路径真被检查到了」。改完校验器要看它有没有立刻抓出存量违规——**抓不出才说明检查没生效**。**字段名错了等于没校验。**
2. **闸门必须覆盖它声称覆盖的全部数据入口。** 当前 6 个：`raw-manifest`·`wrong`·`exams`·`tasks`·`resources`·`data/README.md`，外加 `docs/*.md` 与错题精讲页。**命名/注释必须写明覆盖范围。**
3. **闸门上线前先跑一次看它报什么——自身假阳性会把真错误淹掉。** 五类复发：`startswith` 匹配「I」命中「III」⇒ 整词相等 · 哨兵值（`value=""`／「全部」）当枚举外值 · 题号列「49-56」当实得候选 ⇒ 按列位置判定 · **把「尚未定论」误判成「已定论」**（判据要落在语义状态上）· **按错误的分隔符拆页面内容**（`<br>` 不是换行符）。
4. **「查了数据层」不等于「查了整个事实链」。** 内嵌数据必须加**逐字节比对**闸门（`check_embedded_snapshots`），**修复要用数据层重新生成，不手工改数字**；且**同一事实散落 N 处，改一处就漏 N−1 处——按「事实」建闸门，不是按「文件」建闸门。**
6. **闸门自身的漏洞比没建闸门更危险——它会报「0 错误」让人以为安全。** 复发形态：查「必填」二字而表头填 `| 是 |`；豁免写成 `... or mnote` 而 got=null 的 gotNote 必然非空＝**给所有违规发免死金牌**；`if a != b and a and b` 在 a 为空时短路；上一条免责说明替下一条违规豁免。**只有回退法能暴露，且正反两面都要验**（认不出来的东西要**报错**而不是放过）。定位数字按所在块取窗口，正则要能看见 `<b>7</b> / 8` 这类夹标签写法；比对文本前先按**渲染时的真实分隔规则**切开。
   > ⚠️ **回退法本身会出事**：第十一轮用 `git checkout` 还原测试文件，连带抹掉同文件里的合法修复，而彼时闸门报 0 错误毫不知情。**注入前先 `cp` 备份、还原后逐字节比对 sha256**（`json.dump` 会丢文件末尾换行）——别拿 git 恢复当撤销键。
7. **规范文档是数据入口的一部分，而且是最危险的那个。** 判定按**结构**而非**按关键词全文匹配**。**文档还要写明机器管不到什么**，否则下一个人会误以为已被守住。
8. **修掉一个实例不等于修掉这一类。** 纪律要落成**可自动判定的闸门**，不能只写成「某某要怎样」。
9. **闸门要覆盖事实源头，不能只覆盖派生量。** 加闸门时问：**这条事实从哪来？谁查过源头？**

### done ≠ 做完了

`status: done` 只说明**上一轮自认为**做完了。q5 页的 doneNote 写「五段范式齐备」，实际仍有 5 个真实空缺区块。

> **规程**：即使 `pending: 0` 也不要直接收工，先 grep `待补 ·` 确认真空缺。**判据是页面内容，不是队列状态。** doneNote 只写**亲自核实过**的事实。

**十五轮踩了四种「假 done」，每种更隐蔽**：① HTML 有空缺（grep 抓得到）→ ② HTML 齐了但 JSON 空（**grep HTML 查不到**）→ ③ 两侧都有内容但「对不对」没人查 → ④ **源头事实本身无闸门**。**规程**：交付错题内容是**三处**动作——① 填 HTML 空缺段；② **回写 `data/` 对应 JSON 的同名字段**；③ **两侧符合五段范式**。只做 ①② 属于「假 done」。

### 数据入库与字段坑

JSON · UTF-8 · 2 空格缩进 · 顶层带 `meta`（schema/created/count）· 分值 `full`/`lost` · 答案 `answerKey`+`childAnswer` · 每次入库 = 一次独立 commit。原图存 `RAW/`。

- **错题 `id` 后缀不是题号**（`w-20261002-02` 是第几条记录）——用 `qno` 或从标题抠「第N题」。**`sourceRaw` 可为数组**，多页试卷必然用数组，校验与生成都要兼容。
- **两份 JSON 结构不同**：`data/wrong/*.json` 顶层 `{meta, items}`；`data/exams/*.json` 顶层 `{meta, exams:[…]}`，逐题数据在 `exams[0].wrongs`。直接 `d['wrongs']` 会拿到空。
- **`data/resources/shanghai-papers.json` 是公共试卷资源索引，不是孩子参加过的考试**，纪律上不进 `data/exams/`。
**教材版本**：沪教版（上海）九年级。章节标注以孩子手上那本课本目录为准，`docs/教材版本/` 仍待建。

## 验证纪律

**验证浏览器行为直接上真实浏览器（agent-browser），不要手写 DOM mock。** 2026-10-02 连续 3 次在自写 mock 上犯低级语法错误。

```bash
agent-browser open "file://$(pwd)/x.html"
agent-browser eval "el.click()"              # 比 click 命令可靠
agent-browser eval "localStorage.clear()"    # 测存储前先清
agent-browser close                          # 必须收尾
```

**另：断言「页面坏了」之前先读 `render()` 源码。** 三次踩坑全是这个形态：① 用 `.card.click()` 测而筛选靠 `setF()` ② 两个维度条件相乘得 0 张卡 ③ 按 `h3` 下标取元素而实际有多个 h3。

## Git 约定

`main` 为稳定分支 · `data/` 的 JSON **有意入库**（核心资产）· 提交信息写清**为什么**· 每次错题入库/每张实战表新增 = 一次独立 commit。

## 自动化管道

**`tools/pipeline.sh` 是唯一入口**：ingest 原件 → 生成讲义骨架 → 校验数据 → commit + push。全部幂等，没变化不动 git。

### 脚本与 AI 的分工（硬边界）

脚本**只做确定性填充**，一律不做教学判断：解法步骤、断点分析、变式题、逐题判分、诊断结论全部标 `⚠️ 待补` 并登记到 `data/tasks/pending.json`，由自动化「mySchoolBuddy 教学内容补全」（每 2 小时）补齐。**理由：解法步骤写错了比没有更危险。**

### 生成器防覆盖

**不能拿 `<meta name="generator">` 标记当「是不是人工页」的判据**——人工精修页往往仍带标记（2026-10-03 防护因此失效，又生成一份空壳）。真正判据是**内容是否已实质填写**：exam 侧含「失分在哪」段且「待补」≤4 次；wrong 侧含「断点到底在哪」+「零跳跃分步讲解」且「待补 ·」≤1 次（`is_filled_wrong_page()`）。

**wrong 侧还必须管住「同名」情形**：主循环原先是 `if manual and basename(manual) != fn`——人工页恰在目标路径上时被直接覆盖，且 `pending.json` 仍留着 done，看着一切正常。正确写法：`if manual:` 之后再判 `basename_differs or is_filled_wrong_page(text)`。修完用 sha256 前后比对确认零覆盖。

**数空缺用 `待补 ·`（带间隔号），不要笼统 grep「待补」**——页头「分值待补」标签是合法状态标记（卷面无标注时的正确表达），不是空缺。

### 机器闸门

`tools/validate_schema.py` 是唯一执行者。**校验出错时照常提交、但拒绝推送**，并在 `data/_local/VALIDATION-FAILED.md` 留提醒。

| 纪律 | 机器检查什么 |
|---|---|
| 分值 | `full`/`lost` 为 null 必须 `scorePending: true`，反之亦然 |
| 溯源 | `sourceRaw`（字符串或数组）必须存在于 RAW/ 且已登记 manifest |
| 原件 | sha256 必须一致；不一致时比对 Git HEAD 区分「记录错」与「原件被改」 |
| 答案 | `answerKey`/`childAnswer` 存在、拼写唯一、有 `answerKeySource`、不与作答同串（`check_answer_fields`） |
| 拆解表 | `breakdown` 每行二元组无空格 · `breakdownKey` 条号在范围内 · 页数声明 = 条数 · 页面首列每行能在数据层找到原句（`check_breakdown_faithful`） |
| got 依据 | 含存疑题或自述折算的模块 `got` 必须 null（`check_module_got_grounded`） |
| 跨层一致 / 五段范式 | `check_page_matches_data`（**试卷**页 X/Y 逐模块比对）· `check_five_stage_paradigm`（**错题**精讲页：变式三类配比 / 简单变式须真有数值变化 / 想五题末题须「何时失效」/ steps 须有断点 / 每步三件套 / HTML 标题与 JSON 逐条对应） |

**新增任何数据入口时，同步在 `main()` 里加对应 check。** 当前顺序：`check_wrong` → `check_exams` → `check_tasks` → `check_resources` → `check_cause_enum` → `check_embedded_snapshots` → `check_no_fabricated_score` → `check_module_got_grounded` → `check_page_matches_data` → `check_five_stage_paradigm` → `check_breakdown_faithful` → `check_answer_fields` → `check_papers_derived` → `check_doc_numbers` → `check_data_readme`。

> ⚠️ **命名会误导**：两个 `check_page_*` 各管一半（前者只管试卷页、后者只管错题页）。新增页面类闸门时**在 docstring 第一行写清覆盖哪些页面**。

## 定时任务

launchd plist 在 `tools/launchd/com.myschoolbuddy.pipeline.plist.template`，用 `__REPO__` 占位绝对路径。触发器两套缺一不可：**WatchPaths** + **StartInterval 1800**（休眠兜底）。安装走 `tools/install-launchd.sh install`。
> ⚠️ 本 IDE/沙箱内 shell 无法向 launchd 注册（error 5），且 `launchctl load` 会**返回成功但实际没注册**——必须用 `launchctl print` 确认。
