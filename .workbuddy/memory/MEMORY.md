# mySchoolBuddy · 项目约定

## 交付标准

**讲题类内容一律出单文件 HTML，不要用聊天文字讲题。**

> 来源：2026-10-02 用户明确反馈——"文字讲题是我看得清，不是他看得清，为什么不能用 HTML 清晰组织"。

聊天文字适合我讲清楚，不适合孩子读进去。孩子的认知负荷需要靠**分层、渐进、图形、可交互**来降低，这些在纯文本里做不到。

### 五段范式（硬性标准，已固化进专家技能库）

用户明确要求固定范式："**练一题，看三题，想五题**"。已建 skill `wrong-question-coaching`（专家包内），以后每道错题按此办理。

```
① 原题        →  ② 拆解        →  ③ 零跳跃讲解  →  ④ 三题变式  →  ⑤ 迁移想五题
   全文+原图        条件翻译表        渐进展开         练一题        想五题
```

| 段 | 硬性要求 |
|---|---|
| ① 原题 | **必须置顶**。题干逐字全文（定义句/括号补充/问法一字不省）+ 限定词 `<span class="hl">` 高亮 + 原卷照片（题干裁切 + 整题，折叠）+ 题干拆解表 |
| ② 拆解 | 表格逐句翻译成数学条件，**收尾必须点明"最容易漏的是第几条"** |
| ③ 零跳跃讲解 | 一步一个动作，渐进展开，★ 标记断点。**每步三件套：动作/依据/检验**。舍根与分类讨论单列。最后必须逐个原始条件验证 |
| ④ 三题变式 | **固定配比**：简单变式（只改一个数值）+ 同类型（换考点同手法）+ **问答对调（已知与所求互换）**。答案全部 `<details>` 折叠 |
| ⑤ 迁移想五题 | 抽掉脚手架。3-5 个递进问题，填空+即时判题。**必含"什么情况下这方法失效"**（练适用边界） |

**总时长 25-35 分钟**，超过就是题海。

**问答对调不可省** —— 很多孩子是"记住套路"不是"真懂"，只有把已知和所求对调才能测出来。

**文科适配**（语文/英语/历史/政治/地理）：骨架不变，②拆解改为标注答案在第几段 + 材料层次；③讲解改为**逐句解读文本**（标出定义句/条件句/**答案句**/干扰句）+ 答题模板拆解；④变式改为换材料/换设问方式（概括→原因→评价→启示）；⑤改为题型识别 + 答题角度转换。

### 单文件 HTML 规格

沿用用户既有偏好：

| 项 | 要求 |
|---|---|
| 结构 | 单个 `.html`，内联 CSS/JS，零外部依赖 |
| 宽度 | 正文 max-width 780px 居中 |
| 视觉 | 浅色 Stripe 风格 + 钛金灰 `#1C1C1E` / `#A1A1AA` + 暖金 `#F59E0B` |
| 字体 | 16px 基准（移动端 15.5px），行高 1.75 |
| 响应式 | 断点 600px |
| 命名 | `docs/实战表/学科/题号-主题-精讲.html` |
| 模板 | 专家包内 `skills/wrong-question-coaching/assets/template.html`（已通用化，含 `{{}}` 占位） |

### 讲题页必备结构

**0. 原题（置顶，最先出现）** ← 硬性要求，不可省略

> 来源：2026-10-02 用户反馈——"既然是题目精讲，为什么原题都不给，原题原图是基本条件吧！完整性！"

精讲页**必须**包含，且必须在最前面：

| 元素 | 要求 |
|---|---|
| **题干全文** | 逐字转录，定义句、括号内的补充条件、问法，一个字都不能省 |
| **关键条件高亮** | 把最容易漏的条件（"互为"、"不"、"至少"等）用 `<span class="hl">` 标出 |
| **原卷照片** | 折叠区挂 `<img>`：题干裁切图 + 整题照片（含批改与手写） |
| **题干拆解表** | 把题干逐句翻译成数学条件，指出哪句是陷阱 |

**为什么不能省**：孩子打开页面是**独立阅读**的。没有原题，讲解就悬空——他得先在脑子里重建题目，而他的记忆里存的是"我做错的那题"，不是完整条件。

**图像资源**：

- 原图归档 `data/_scans/YYYY-MM-DD/`，**该目录会被清空**（含个人信息不入 Git），用前先确认存在
- 建议同时存**题干裁切图**（`sips -c 高 宽 --cropOffset y x`）+ **整题图**
- 页面用相对路径引用，如 `../../../data/_scans/2026-10-02/q19-math.jpg`
- 交付前必须用真实浏览器验证 `img.naturalWidth > 0`

1. **图形先行** —— 抽象关系先给图，再讲文字
2. **已做对的部分** —— 表格逐项对照，先建立信心再谈错点
3. **断点定位** —— 把错误答案摆在旁边对比，**说清楚错值是怎么来的**
4. **分步法（渐进展开）** —— 一步一个动作，**不做完上一步不能跳下一步**
5. **坑的形态** —— 对照表列出「错误做法 / 问题 / 正确路径」
6. **检验题** —— 2 道，**答案默认折叠**（用户讨厌剧透）
7. **复述检验** —— 填空 + 即时判题，验证「看懂」还是「会用」
8. **家长区** —— 深色卡片，具体到分钟的动作

### 交互约定

| 交互 | 用途 |
|---|---|
| 渐进解锁 | 未完成前一步则下一步 `locked`，强制顺序 |
| 进度持久化 | `localStorage`，key 格式 `msb.<题目>.progress.v1` |
| 即时判题 | 关键词宽松匹配，答错只提示不直接给答案 |
| 折叠答案 | `<details>`，防剧透 |
| 复制按钮 | 代码块 hover 显示 |
| 重置按钮 | 清空进度，需 `confirm` |

## 数据纪律

### 错因判定纪律（重要）

**仅凭最终答案判错因会误判。必须回看中间步骤。**

2026-10-02 的 q19 就是教训：孩子的最终答案错了，但中间列出的方程完全正确。仅看答案会判成「概念不清」（错），回看步骤才看出是「方法没想到」（对）。

- 录入错题时，**必须附中间步骤判读**，不能只看答案行
- 「概念不清」与「方法没想到」的救法完全相反，混淆会导致无效刷题
  - 概念不清 → 回教材重读概念
  - 方法没想到 → 归类题型 + 练固定动作

### 分值纪律

**照片上没有分值标注就留 `null` + `scorePending: true`，绝不估算。** 缺分值不能计入失分点热区统计。

- **反向也成立**：卷面**明确标了**单题分值（如 V-D「第 57-60 题每题 2 分」）就要**回填**，
  留 null 是失职。判据是「照片上有没有」，不是「推算得出来吗」。
- **算不出合计就不给合计**。分项里有一处得分不明（红笔未明示）就别写「已确认实得 X 分」——
  无依据的合计数字比没有更糟，它会被当成结论引用。

### cause 字段纪律

**`cause` 只能是五类枚举之一**（概念不清 / 方法没想到 / 计算失误 / 审题错误 / 表达不规范），
长描述放 `causeNote`。**只能选一个主因**，副因放 `causeSecondary`。

> 2026-10-03 教训：`cause` 被塞了「审题错误 + 补数漏步」「辨词不细：……」这类长句，
> 校验器 8 条警告，五类统计会全部漏掉这些题——**看起来有数据，实际统计不出来**。
> 存疑项用 `causePending: true` 标出，不硬归类。

### 核卷纪律

**判分前必须放大原卷，不能看缩略图下判断。**

2026-10-03 教训：p3 缩略图上第 46 题的红笔 × 看着像判错，放大后确认是**划掉三个干扰项**、
学生选 D 正确。若按缩略图判，「V-B 全对」会被误改成「错 1 题」——**误判比漏判更危险**。

```bash
sips -c 高 宽 --cropOffset y x 原图.jpg --out /tmp/x.jpg   # 裁切
sips -Z 2000 /tmp/x.jpg --out /tmp/x-big.jpg                # 放大后再看
```

### 数据入库

- JSON，UTF-8，2 空格缩进
- 顶层带 `meta`（schema / created / count）
- 分值字段：`full` / `lost`
- 对比字段：`answerKey`（正确答案）+ `childAnswer`（孩子原答案）
- 原图存 `RAW/`（已入 Git，是事实依据层）。**页面必须引 `RAW/`，不要引 `data/_scans/`**（已 gitignore，远端必断链）
- 每次入库 = 一次独立 commit

## 验证纪律

**验证浏览器行为直接上真实浏览器（agent-browser），不要手写 DOM mock。**

2026-10-02 教训：连续 3 次在自写 mock 脚本上犯低级语法错误，浪费多轮。

```bash
agent-browser open "file://$(pwd)/x.html"
agent-browser eval "el.click()"        # 比 click 命令可靠

```

## 自动化管道

**`tools/pipeline.sh` 是唯一入口**：ingest 原件 → 生成讲义骨架 → 校验数据 → commit + push。全部幂等，没变化不动 git。

### 脚本与 AI 的分工（硬边界）

脚本**只做确定性填充**，一律不做教学判断：解法步骤、断点分析、变式题、逐题判分、诊断结论全部标 `⚠️ 待补` 并登记到 `data/tasks/pending.json`，由 WorkBuddy 自动化「mySchoolBuddy 教学内容补全」（每 2 小时）补齐。

> 理由：解法步骤写错了比没有更危险。

### 生成器标记（防覆盖机制）

自动生成的页面头部带 `<meta name="generator" content="generated-by: tools/build_skeletons.py">`。

- **带标记** → 可被重新生成
- **不带标记** → 人工成果，**绝不允许覆盖**（如 q19 精讲页是逐字对照手写过程改出来的）

⚠️ **但不能拿这个标记当「是不是人工页」的判据**——人工精修页往往仍带标记（脚本生成骨架后
被逐字改出来的，如 q5 与英语拆解页）。真正的判据是**内容是否已实质填写**：
exam 侧为含「失分在哪」段且「待补」出现 ≤4 次；wrong 侧为含「断点到底在哪」+
「零跳跃分步讲解」且「待补 ·」≤1 次（`is_filled_wrong_page()`）。2026-10-03 首次修防重复逻辑时用标记当判据，
防护直接失效又生成一份空壳。

**wrong 侧还必须管住「同名」情形**（2026-10-03 修）。主循环原先是
`if manual and basename(manual) != fn`——**人工页恰好就在目标路径上时会被直接覆盖**，
且 `pending.json` 仍留着 done，看着一切正常。正确写法：`if manual:` 之后再判
`basename_differs or is_filled_wrong_page(text)` 才跳过。修完用 sha256 前后比对确认零覆盖。

**数空缺要区分占位与合法标记**：页头「分值待补」标签是合法状态标记（卷面无分值标注时的
正确表达），不是空缺区块。数空缺用 `待补 ·`（带间隔号）这个占位块特征串，或直接数
`⚠️ 待补` 块，不要笼统 grep「待补」两个字。

生成器遇到同题号的人工页会跳过，并在任务队列登记 `wrong-refine`，让 AI 把内容补进已有页而非新开一页。

> **空壳页比没有页面更糟**：它看起来是有效交付物，实际是空数据，且每次跑管道都会新开一份。
> 根因是脚本按 `name` 造文件名、人工页用纯日期命名，两者永远对不上。exam 侧已于 2026-10-03 加防护。

### done ≠ 做完了（2026-10-03 教训）

`pending.json` 里 `status: done` 只说明**上一轮自认为**做完了，不等于页面真的有内容。
q5 精讲页的 doneNote 写着「五段范式齐备」，实际仍有 **5 个真实「⚠️ 待补」空缺区块**——
记录与事实不符，队列显示 pending: 0 却什么都没交付。

> **规程**：即使 `pending: 0` 也要收工，也先 grep 一遍 `待补 ·` 确认真空缺再决定。
> 判据是**页面内容**，不是队列状态。写 doneNote 时只写**亲自核实过**的事实。

### 三条硬纪律的机器闸门

`tools/validate_schema.py` 是唯一执行者。**校验出错时照常提交、但拒绝推送**，并在 `data/_local/VALIDATION-FAILED.md` 留提醒——问题必须让人看见，悄悄跳过才最危险。

| 纪律 | 机器检查什么 |
|---|---|
| 分值 | `full`/`lost` 为 null 必须 `scorePending: true`，反之亦然 |
| 溯源 | `sourceRaw`（字符串或数组）必须存在于 RAW/ 且已登记 manifest |
| 原件 | sha256 必须一致；不一致时比对 Git HEAD 区分「记录错」与「原件被改」，后者拒绝自动修复 |

### ⚠️ 「0 错误」可能只是没检查到（2026-10-03 教训）

**校验器只覆盖一部分数据时，0 错误是假象。** 本项目已连犯两次：

| # | 漏网的数据 | 后果 |
|---|---|---|
| 1 | 上一轮 q5 的 doneNote 声称「五段范式齐备」 | 实际有 5 个真空缺「待补」区块 |
| 2 | **exam 的 `wrongs` 数组从未进校验** | 36/58/61 分值 null 却没标 scorePending，被当成「没失分」 |

> 规律：**新增数据入口时必须同步在校验器加对应检查**，否则新数据等于无约束。
> 判据不是「校验通过了」，而是「**该数据路径真的被检查到了**」——改完校验器要看它有没有立刻抓出存量违规，
> 抓不出才说明检查没生效。

**字段名错了等于没校验**：exam 报错曾用 `w.get('no')`，实际是 `qno`，所有报错都显示「第?题」。
报错信息里读不出定位信息，等于把错误藏起来了。

### 数据字段坑

- **错题 `id` 后缀不是题号**：`w-20261002-02` 是第几条记录。必须用 `qno` 字段或从标题抠「第N题」，否则会生成 `q1-…` 而卷面写的是 q19。
- **`sourceRaw` 可为数组**：多页试卷必然用数组，校验与生成都要兼容两种形态。
- **两份 JSON 结构不同**：`data/wrong/*.json` 顶层是 `{meta, items}`；`data/exams/*.json` 顶层是 `{meta, exams:[…]}`，逐题数据在 `exams[0].wrongs`。直接 `d['wrongs']` 会拿到空。

## 定时任务

launchd plist 在 `tools/launchd/com.myschoolbuddy.pipeline.plist.template`，用 `__REPO__` 占位绝对路径。触发器两套缺一不可：**WatchPaths**（目录变化即跑）+ **StartInterval 1800**（休眠兜底）。

> ⚠️ 本 IDE/沙箱内 shell 无法向 launchd 注册服务（error 5），且 `launchctl load` 会**返回成功但实际没注册**——必须用 `launchctl print` 确认。安装走 `tools/install-launchd.sh install`，装完在真终端验证。
