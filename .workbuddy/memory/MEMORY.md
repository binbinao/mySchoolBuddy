## 交付标准

**讲题类内容一律出单文件 HTML，不用聊天文字讲题**（用户原话："文字讲题是我看得清，不是他看得清"）。

### 五段范式（硬性）

① 原题 → ② 拆解 → ③ 零跳跃讲解 → ④ 三题变式 → ⑤ 迁移想五题。skill `wrong-question-coaching`（闸门 `check_five_stage_paradigm`）。总时长 25-35 分钟。

| 段 | 硬性要求 |
|---|---|
| ① 原题 | **置顶**。题干**逐字**全文 + 限定词 `<span class="hl">` + 原卷照片（折叠）+ 题干拆解表 |
| ② 拆解 | 逐句翻译成条件，收尾点明「最容易漏的是第几条」 |
| ③ 零跳跃 | 一步一动作，★ 标断点，每步三件套（动作/依据/检验），末尾逐条件验证 |
| ④ 三题变式 | **配比固定**：简单变式 + 同类型 + **问答对调**。答案全 `<details>` |
| ⑤ 想五题 | 3-5 递进问，填空+即时判题，**末题必为「什么情况下这方法失效」** |

**问答对调不可省**——很多孩子是「记住套路」不是「真懂」。文科（语/英/史/政/地）骨架不变：②标注答案在第几段+材料层次；③逐句解读文本（定义/条件/答案/干扰句）；④换材料换设问；⑤题型识别+角度转换。

### 单文件 HTML 规格

单 `.html`、内联 CSS/JS、零外部依赖 · max-width 780px · 浅色 Stripe + 钛金灰 `#1C1C1E`/`#A1A1AA` + 暖金 `#F59E0B` · 16px/行高1.75/断点600px · 命名 `docs/实战表/学科/题号-主题-精讲.html`。

**图像只引 `RAW/`**（已入 Git，事实依据层），**绝不引 `data/_scans/`**（gitignore + 含个人信息，远端必断链）。交付前用真实浏览器验证 `img.naturalWidth > 0`。

**必备结构**：图形先行 → 已做对的部分 → 断点定位 → 分步法 → 坑的形态对照表 → 检验题 2 道（答案折叠，用户讨厌剧透）→ 复述检验 → 家长区（深色卡片，具体到分钟）。
**交互**：渐进解锁 · `localStorage`（key `msb.<题目>.progress.v1`）· 即时判题（关键词宽松匹配，答错只提示不给答案）· `<details>` · 复制按钮 · 重置需 `confirm`。

## 数据纪律

### 四条源头规则

1. **错因**：`cause` 只能五类之一（概念不清/方法没想到/计算失误/审题错误/表达不规范），长描述放 `causeNote`，**只选一个主因**。`causeSecondary` 同为五类且与主因不同，**只写本次真犯的第二处错**（潜在隐患不是副因）。**`causePending: true` ⇒ `cause` 必须为空**。判据必须写出来（`causeNote`/`myThought`），「粗心。」这类套话非法。五类在仓库 7 处定义，靠人记必分叉——定义源 `docs/方法论/错因分类与复习排期.md`，其余六处由 `check_cause_enum()` 逐字比对。**第五类是「表达不规范」不是「时间不够」**。生成器必须跳过存疑题。
2. **答案**：规范拼写只有 `answerKey`（反推的必配 `answerKeySource`）与 `childAnswer`（原样保留批注痕迹），无别名。**答案错了整套教学判断全部反着走**。
3. **题干拆解**：`stem`（逐字全文）· `breakdown`（`[[题干原句, 翻译成条件]]`，左边必须是原句）· `breakdownKey`（N 在范围内）· 页数 = `len(breakdown)`。
4. **已做对**：`doneRight`（[[他写下的, 为什么对]]，逐项对照原卷手写）· `doneWrong`（[[他做错的, 错在哪]]= **断点直接证据**）。**只记 ✓ 不记 ✗ ⇒ 断点从证据退化成推断**。

字段细则与能力边界表在 **`data/README.md`**（规范源，闸门 `check_data_readme` 查它有没有写明边界）。

### 分值

**判据是「照片上有没有」，不是「推算得出来吗」。** 没印单题分值 → `null` + `scorePending: true`，绝不估算；卷面明确印了（如「第 57-60 题每题 2 分」）→ **必须回填**，留 null 是失职。分项有一处不明就别给合计，模块/全卷 `got` 同样可为 null + `gotNote`。

### 错因判定

**仅凭最终答案判错因会误判，必须回看中间步骤。** q19：最终答案错但中间方程全对——只看答案会误判成「概念不清」，回看步骤才是「方法没想到」。**二者救法完全相反**，混淆=无效刷题。

### 核卷

**判分前必须放大原卷，不能看缩略图。误判比漏判更危险。**
`sips -c 高 宽 --cropOffset y x x.jpg --out /tmp/x.jpg` 裁切 → `sips -Z 2000 /tmp/x.jpg --out /tmp/x-big.jpg` 放大。
四次教训：① 红笔 × 可能是划干扰项；② 一条长斜线 ≠ 逐题批改；③ 只标大题总分 ≠ 可折算；④ 页面把双向条件写成单向，**只有放大逐字读才看得出**。

### 教材类事实：信息源优先级（2026-10-04 血泪）

**教辅站 < 历年真题 < 孩子手上课本照片 < 学校/老师明确告知**

向量一事我连错两次，且方向相反：① 据教辅站目录说「向量还在、项目记载错了」→ 错（教辅站「2024」标签下混着旧版内容）；② 据真题说「教材删了但考纲照考、应该练」→ 方向也不对。**两次都败在同一个地方：没有先问她。**
⇒ **任何教材/考纲类事实，先问学校口径，再动手查。** 用户与孩子妈妈是「事实源」，不是「数据录入员」。

**工具 `tools/mine_exam_scope.py`**：从 `RAW/试卷库/` 真题反推考点权重，两步法——**先词频定位，再抽验上下文**。第二步不能省（词频高 ≠ 对她适用）。⚠️ 爬虫剥了数学符号，**只能词频定位不能读题**，读题回看 `RAW/试卷库/原卷扫描/*.png`。


### 跨层一致性

**同一事实在数据层与所有页面必须一致。打架时不选边站，回原卷裁决。** 裁决原则：找出「**两边都缺依据**的那个共同前提」，显式记成 null。

## ⚠️ 闸门纪律（展开见 `.workbuddy/memory/reference/闸门纪律.md`）

已连犯**十八类「0 错误也抓不到」的缺陷**。六种形态：**①** 漏字段/漏入口/把错误藏起来（字段名写错 ⇒ 报错读不出定位，等于没查）· **②** 检查本身抓不到（「HTML 齐了 JSON 空」按定义 grep HTML 查不到；「修掉一个实例」被「已处理过了」锚定；**正则失配时 `if m:` 判否无兜底 ⇒ 静默放过**——第 18 类：README 里 `"cause"` 与 `causeSecondary` 合成一行，枚举比对点直接消失，**通过数 111→110 而 0 错误**）· **③** 副本漂移/静默失效（同概念两套拼写各自自洽，页面照常渲染）· **④** 规范反了（只查数据对不对，没查教人写数据的文档）· **⑤** **源头无闸门**（14 `answerKey`·15 `stem`/`breakdown`·16 `doneRight`/`doneWrong`·17 `cause*`——闸门围着派生量建，源错了派生量一致地错）· **⑥** 内容无闸门（精讲页是唯一承载教学判断的产物，却只被查过「非空」）。

> **加闸门时必问**：这条事实**从哪来**？谁查过它的**源头**？**页面比数据层多出信息，本身就是一条告警信号。**
> 下一个候选缺口：④ 段 `variants` 与 ⑤ 段 `thinkQuestions` 的内容正确性（只查了配比与结构，题目本身对不对没人查）。

**新数据入口八问**：① 结构/必填 ② 枚举合法性 ③ 溯源存在性 ④ **页面级对应** ⑤ **副本/派生** ⑥ **回退法自证（正反两面）** ⑦ **事实源头**——原始事实还是推出来的 ⑧ **字段是否真的存在**。前 12 轮漏的几乎都是 ④⑤⑥。

**铁律速查**（每条的踩坑实例见展开版与 automations 记忆）：

1. **「0 错误」可能只是没检查到**——改完校验器要看它有没有立刻抓出存量违规，**抓不出才说明检查没生效**。**字段名错了等于没校验。**
2. **闸门必须覆盖它声称覆盖的全部入口**（当前 6 个 + `docs/*.md` + 精讲页），命名/注释必须写明覆盖范围。
3. **上线前先跑一次看它报什么**——自身假阳性会把真错误淹掉。六类复发：`startswith` 让「I」命中「III」· 哨兵值当枚举外值 · **把「尚未定论」误判成「已定论」** · 按错误分隔符拆内容 · 判据太严（比**事实标记**而非整句字面）· 判据前提是「违规内容本不具备的性质」（恒假＝免死金牌）。
4. **「查了数据层」不等于「查了整个事实链」**——内嵌数据逐字节比对，**修复要用数据层重新生成**；**同一事实散落 N 处，按「事实」建闸门不是按「文件」建闸门。**
5. **规范文档是数据入口的一部分，而且最危险**——按**结构**判定，且**要写明机器管不到什么**。
6. **闸门自身的漏洞比没建闸门更危险**——**只有回退法能暴露，正反两面都要验**。⚠️ 回退法本身会出事：`git checkout` 还原测试文件会抹掉同文件里的合法修复 ⇒ **先 `cp` 备份、还原后比对 sha256**。⚠️ 用例也会设计错。**闸门报错时先怀疑用例，别急着调阈值。**
7. **修掉一个实例不等于修掉这一类**——纪律要落成**可自动判定的闸门**。
8. **派生量不手写**——每个写入方都要现算；「本次运行」的数据（增量、unchanged）根本不该落盘。
9. **`docs/*.md` 是第五个漂移面**——只审能自动判定的事实，不做全文数字正则扫描。**覆盖广但靠关键词打补丁的闸门，不如按定义能自动判定的窄口径。**

### done ≠ 做完了

`status: done` 只说明**上一轮自认为**做完了。**即使 `pending: 0` 也不要直接收工**，先 grep `待补 ·`（带间隔号，页头「分值待补」标签是合法状态标记）确认真空缺。**判据是页面内容，不是队列状态。**

五种「假 done」：① HTML 有空缺 → ② HTML 齐了但 JSON 空（grep HTML 查不到）→ ③ 两侧都有内容但「对不对」没人查 → ④ 源头事实无闸门 → ⑤ **数据层根本没有承载该事实的字段**。
**交付错题内容是三处动作**：① 填 HTML 空缺段；② **回写 `data/` 同名字段**（先确认字段存在，不存在就是第 ⑤ 类）；③ 两侧符合五段范式。

## 数据入库与字段坑

JSON · UTF-8 · 2 空格 · 顶层带 `meta`（schema/created/count）· 原图存 `RAW/` · 教材版本沪教版（上海）九年级。

- **错题 `id` 后缀不是题号**（`w-20261002-02` 是第几条记录）——用 `qno`。**`sourceRaw` 可为数组**（多页试卷必然用数组）。
- **两份 JSON 结构不同**：`data/wrong/*.json` = `{meta, items}`；`data/exams/*.json` = `{meta, exams:[…]}`，逐题在 `exams[0].wrongs`，卷层主键叫 `id` 不叫 `examId`。直接 `d['wrongs']` 会拿到空。
- **`data/resources/shanghai-papers.json` 是公共试卷资源索引**，不是孩子参加过的考试，不进 `data/exams/`。
- **范围确认**：`app/index.html` 用 localStorage、不读 `data/*.json`，设计如此，**不算漏网入口**。
- **拼写分裂**：两个脚本写同一个 JSON、页面读错拼那个 ⇒ 新条目同时失去徽章/筛选/统计，**页面不报错**。凡两个脚本写同一文件先核对键名。

## 验证纪律

**验证浏览器行为直接上真实浏览器（agent-browser），不要手写 DOM mock。**
`agent-browser open "file://$(pwd)/x.html"` → `agent-browser eval "el.click()"`（eval 比 click 可靠）→ 测存储前先 `localStorage.clear()` → **必须 `agent-browser close` 收尾**。
**断言「页面坏了」之前先读 `render()` 源码。** 三次踩坑：用 `.card.click()` 测而筛选靠 `setF()` · 两个维度条件相乘得 0 张卡 · 按 `h3` 下标取元素。

## 自动化管道

**`tools/pipeline.sh` 是唯一入口**：ingest 原件 → 生成讲义骨架 → 校验数据 → commit + push。全部幂等，没变化不动 git。

**脚本与 AI 的分工（硬边界）**：脚本**只做确定性填充**，一律不做教学判断（解法步骤、断点分析、变式题、逐题判分、诊断结论全标 `⚠️ 待补` 并登记 `data/tasks/pending.json`）。**理由：解法步骤写错了比没有更危险。**

**机器闸门**：`tools/validate_schema.py`（124K）是唯一执行者。**校验出错时照常提交、但拒绝推送**，并在 `data/_local/VALIDATION-FAILED.md` 留提醒。当前 18 个 check 的调用顺序见 `main()`（文件末尾）。**新增任何数据入口时同步在 `main()` 里加对应 check。**

**生成器防覆盖**：**不能拿 `<meta name="generator">` 当「是不是人工页」的判据**（人工精修页往往仍带标记，2026-10-03 防护因此失效又生成一份空壳）。真正判据是**内容是否已实质填写**：exam 侧含「失分在哪」且「待补」≤4 次；wrong 侧含「断点到底在哪」+「零跳跃分步讲解」且「待补 ·」≤1 次（`is_filled_wrong_page()`）。**wrong 侧还要管住「同名」情形**——人工页恰在目标路径上时不能被覆盖，写法是 `if manual:` 之后再判 `basename_differs or is_filled_wrong_page(text)`，修完用 sha256 前后比对确认零覆盖。
**生成器只写 `docs/实战表/<学科>/`**，`docs/整卷分析/` 不在它管辖内，是人工页。

**定时任务**：plist 模板 `tools/launchd/com.myschoolbuddy.pipeline.plist.template`（`__REPO__` 占位），**WatchPaths + StartInterval 1800 两套缺一不可**。安装走 `tools/install-launchd.sh install`。⚠️ 沙箱内 shell 无法向 launchd 注册（error 5），且 `launchctl load` 会**返回成功但实际没注册**——用 `launchctl print` 确认。

`main` 为稳定分支 · `data/` 的 JSON **有意入库**（核心资产）· 提交信息写清**为什么**· RAW 入库与 data 解析分开提交 · 每次错题入库/每张实战表新增 = 一次独立 commit · 仓库含孩子个人信息，**保持私有**。
