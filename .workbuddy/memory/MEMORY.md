# mySchoolBuddy · 项目约定

## 交付标准

**讲题类内容一律出单文件 HTML，不要用聊天文字讲题。**

> 2026-10-02 用户反馈——"文字讲题是我看得清，不是他看得清"。孩子的认知负荷要靠**分层、渐进、图形、可交互**降低，纯文本做不到。

### 五段范式（硬性标准）

固定范式"**练一题，看三题，想五题**"，已建 skill `wrong-question-coaching`。
`① 原题 → ② 拆解 → ③ 零跳跃讲解 → ④ 三题变式 → ⑤ 迁移想五题`

| 段 | 硬性要求 |
|---|---|
| ① 原题 | **必须置顶**。题干逐字全文（定义句/括号补充/问法一字不省）+ 限定词 `<span class="hl">` 高亮 + 原卷照片（题干裁切+整题，折叠）+ 题干拆解表 |
| ② 拆解 | 表格逐句翻译成数学条件，**收尾点明"最容易漏的是第几条"** |
| ③ 零跳跃讲解 | 一步一个动作，渐进展开，★ 标断点。**每步三件套：动作/依据/检验**。舍根与分类讨论单列。末尾逐个原始条件验证 |
| ④ 三题变式 | **固定配比**：简单变式（只改一个数值）+ 同类型（换考点同手法）+ **问答对调（已知与所求互换）**。答案全 `<details>` 折叠 |
| ⑤ 迁移想五题 | 抽掉脚手架。3-5 个递进问题，填空+即时判题。**必含"什么情况下这方法失效"** |

**总时长 25-35 分钟**，超过就是题海。**问答对调不可省**——很多孩子是"记住套路"不是"真懂"，只有对调才能测出来。

> ⚠️ **这五条是硬性标准，已落成机器闸门 `check_five_stage_paradigm()`（第十三轮新增）**——此前它们只写在文档里、内容对错无人查。改这五段内容前先想好会不会被它拦下。

**文科适配**（语文/英语/历史/政治/地理）：骨架不变。②改为标注答案在第几段+材料层次；③改为**逐句解读文本**（定义句/条件句/**答案句**/干扰句）+ 答题模板拆解；④改为换材料/换设问（概括→原因→评价→启示）；⑤改为题型识别+答题角度转换。

### 单文件 HTML 规格

| 项 | 要求 |
|---|---|
| 结构 | 单个 `.html`，内联 CSS/JS，零外部依赖 |
| 宽度 | 正文 max-width 780px 居中 |
| 视觉 | 浅色 Stripe 风格 + 钛金灰 `#1C1C1E`/`#A1A1AA` + 暖金 `#F59E0B` |
| 字体 | 16px 基准（移动端 15.5px），行高 1.75，断点 600px |
| 命名 | `docs/实战表/学科/题号-主题-精讲.html` |
| 模板 | 专家包内 `skills/wrong-question-coaching/assets/template.html`（含 `{{}}` 占位） |

**图像资源**：原图归档 `data/_scans/YYYY-MM-DD/`（**该目录会被清空**，含个人信息不入 Git）。建议同时存题干裁切图（`sips -c 高 宽 --cropOffset y x`）+ 整题图。**页面必须引 `RAW/`，不要引 `data/_scans/`**（已 gitignore，远端必断链）。**交付前必须用真实浏览器验证 `img.naturalWidth > 0`**。

**其他必备结构**：图形先行 → 已做对的部分（先建信心）→ 断点定位 → 分步法 → 坑的形态对照表 → 检验题 2 道（答案折叠，用户讨厌剧透）→ 复述检验 → 家长区（深色卡片，具体到分钟）。

**交互约定**：渐进解锁 · `localStorage` 进度持久化（key `msb.<题目>.progress.v1`）· 即时判题（关键词宽松匹配，答错只提示不给答案）· `<details>` 折叠答案 · 代码块复制按钮 · 重置需 `confirm`。

## 数据纪律

### 错因判定纪律

**仅凭最终答案判错因会误判，必须回看中间步骤。** 2026-10-02 q19：最终答案错但中间方程完全正确——只看答案会判成「概念不清」（错），回看步骤才是「方法没想到」（对）。二者救法完全相反，混淆会导致无效刷题。录入错题**必须附中间步骤判读**。

### 分值纪律

**照片上没有分值标注就留 `null` + `scorePending: true`，绝不估算。** 缺分值不能计入失分热区统计。

- **反向也成立**：卷面**明确标了**单题分值（如 V-D「第 57-60 题每题 2 分」）就要**回填**，留 null 是失职。判据是「照片上有没有」，不是「推算得出来吗」。
- **算不出合计就不给合计**。分项里有一处得分不明就别写「已确认实得 X 分」——无依据的合计数字比没有更糟，它会被当成结论引用。
- **模块/全卷 `got` 同样可为 null**，留 null 必须在 `gotNote` 写明为何不折算。**含 `uncertain` 题的模块 got 必须为 null**——红笔未明示扣分就不能按「没红笔就算对」推定 0 失分。
- **⚠️ 这条是「一类」不是「一例」**（第十二轮复发）。第五轮据此把听力改成 null，**III 完形 `got=7`、IV 句子完成 `got=8` 却照样留着**——`7` 是「8 题对 7 题」的**题数被当成分数**。**别问「哪个模块要留空」，要问「这个数有没有卷面依据」。** 闸门 `check_module_got_grounded()` 按可自动判定口径覆盖（存疑题 / gotNote 自述折算），不靠人记模块名。
- **规范源是 `data/README.md` 的「分值纪律」章节**（第十一轮修正）。此前写「`full`/`lost` 必填」，**与本纪律完全相反**，照它录数据会诱导估算。闸门 `check_data_readme()` 已覆盖。

### cause 字段纪律

**`cause` 只能是五类枚举之一**（概念不清/方法没想到/计算失误/审题错误/表达不规范），长描述放 `causeNote`。**只能选一个主因**，副因放 `causeSecondary`。**存疑用 `causePending: true`，不硬归类**——它同时是第十四道闸门里「答案是否必填」的判据（未定论 ≠ 已判因）。

> 教训：`cause` 被塞「审题错误 + 补数漏步」这类长句，校验器 8 条警告，五类统计全部漏掉——**看起来有数据，实际统计不出来**。

错因五类在仓库里有 **7 处定义**，靠人记必分叉。**定义源是 `docs/方法论/错因分类与复习排期.md`**，其余六处必须逐字一致：`validate_schema.py` 的 `CAUSES` · `app/index.html` 的 `#w-cause` · `#f-cause` · **`const ci`（错因 chip 着色，缺项静默退化默认灰 `c0`，肉眼核验通不出错）** · `README.md` schema 示例 · `build_skeletons.py` 的 `CAUSE_TONE`。机器闸门 `check_cause_enum()` 已做七处比对。**第五类是「表达不规范」，不是「时间不够」**——后者是条件不是病因（考试做不完的真因通常是「卡壳不会跳过」，归 `方法没想到`，救法加限时套卷）。

### 核卷纪律

**判分前必须放大原卷，不能看缩略图下判断。误判比漏判更危险。**

```bash
sips -c 高 宽 --cropOffset y x 原图.jpg --out /tmp/x.jpg   # 裁切
sips -Z 2000 /tmp/x.jpg --out /tmp/x-big.jpg                # 放大后再看
```

三次教训：① p3 缩略图上第 46 题的红笔 × 看着像判错，放大后确认是**划掉三个干扰项**、选 D 正确。② 光标下**一条长斜线 ≠ 逐题批改**——IV 36/37 下方看着各有红笔，放大追踪笔画后确认是老师一次性拉的长斜线，两题均无单独 √，差点被缩略图洗掉一处存疑失分。③ **只标大题总分不等于可折算**——III 标题只印「…only be used once.（8 分）」共 8 空、IV 只印「…as required.（10 分）」共 5 空，都无单空分值，**判据是「照片上有没有印单题分值」，不是「这个模块错几题能算出来」**。

### 跨层一致性纪律

**同一事实在数据层与所有页面必须一致。发现打架时不要选边站，要回到原卷裁决。**

> **裁决原则**：两侧冲突时，正确解不是挑一个信，而是**找出「两边都缺依据」的那个共同前提**，显式记成 null。

实例（第五轮）：`modules[I 听力].got=25`（满分）却在同一行 evidence 写「11 仅错 1 空」且 wrongs 里有第 11 题，同时两页分别写 25/25 与 24/25。裁决：卷面听力 C 只标「10 分」共 5 空、无单空分值，24 与 25 **都是 10÷5 折算，两个都不能用** → `got` 留 **null** + `gotNote`，两页同步不给具体实得。**第十二轮复发一次**（句子完成跨页写 9/10，且把题数 23 当成满分），已由 `check_page_matches_data()` 逐模块比对。

### 答案字段纪律（第十四轮新增）

**答案是数据层的「事实源头」，此前十四轮十几道闸门一道都没查过它。**

`childAnswer` 决定「已做对的部分」能写什么、`answerKey` 决定「断点到底在哪」才成立。
**答案错了整套教学判断全部反着走，而孩子会照着错答案继续练**——比分值估错严重得多。

**规范拼写只有两个，不接受别名**：

| 字段 | 含义 | 纪律 |
|---|---|---|
| `answerKey` | 正确答案 | 必填（有 `cause` 且非 `causePending` 时）。反推的必须配 `answerKeySource` |
| `childAnswer` | 孩子原答案 | 必填（同上）。原样保留批注痕迹 |

**已清掉的存量拼写分裂**（第十轮铁律五的同型）：
`correctAnswer`（与 `answerKey` 同义、**全站零读取方**）、`myAnswer`（与 `childAnswer` 同义，
生成器曾用 `childAnswer or myAnswer` 兜底 ⇒ 改错那个会静默生效）。
`stemHtml` 同理——数据层**根本没有这个键**，生成器却把它排在 `stem` 前面读。

> **`or` 兜底链是拼写分裂的温床**：它让两种拼写可以长期并存且都不报错。
> **一个键不能有两个意思。** 要么二选一，要么显式写清回落顺序。

**⚠️ 机器守结构，守不住语义**（必须写进规范，否则下一个人会误以为已守住）：
把第 11 题 `answerKey` 从 `stay balanced` 改成 `give up smoking`，校验器**不报错**——
英语/语文答案是自由文本，机器判不了对错。**这是能力边界不是漏洞。**
`check_answer_fields()` 只保证「答案存在、拼写唯一、有依据、与孩子作答不是同一串」。
「答案正确」只能靠**核卷**与**人工复算**。

### ⚠️ 闸门纪律（九条，十四轮反复踩坑的核心）

本项目已连犯**十四类「0 错误也抓不到」的缺陷**：

| # | 缺陷 | 为什么抓不到 |
|---|---|---|
| 1 | HTML 有 `待补 ·` 空缺 | grep 能抓到 |
| 2 | 校验器漏 `exam.wrongs` | 0 错误是假象 |
| 3 | 字段名错成 `no`（实为 `qno`） | 报错显示「第?题」＝把错误藏起来 |
| 4 | HTML 齐了但 JSON 空 | 按定义 grep HTML 查不到 |
| 5 | 模块 got 与本模块失分题矛盾 + 跨页数字打架 | 单看任一处都「像对的」 |
| 6 | 闸门只覆盖了一半数据入口 | 只验一侧＝半个闸门 |
| 7 | 手工统计数字漂移（`data/resources/` 从未被校验） | 增量与总量混用 |
| 8 | 页面内嵌副本与数据层漂移（试卷地图页 `const DATA`） | 闸门作用于「磁盘上的 JSON」，漂移发生在「JSON 被拷贝进 HTML 之后」 |
| 9 | 跨页修订的漏网残留（提示条宣布作废、正文仍引用） | 「散文数字」既不在 JSON 也不在 `const` 块 |
| 10 | 同一概念两套拼写 + `docs/*.md` 是第五个漂移面 + 派生量手写 | 见下 |
| 11 | 规范文档把纪律写反（`data/README.md` 教人必填分值） | 前十类都在查「数据对不对」，从没查过「教人写数据的文档对不对」 |
| 12 | **修掉一个实例没修掉这一类**（听力改了 null，III/IV 照旧写 7 和 8） | 注意力被「听力已经处理过了」锚定，同一逻辑换个模块就看不见 |
| 13 | **页面级闸门只审 exams 侧，错题精讲页内容完全无闸门** | `check_page_matches_data` 从 `data/exams/` 取事实；`data/wrong` 的内容只被查过「非空」 |
| 14 | **事实源头（答案字段）完全无闸门** | 前十三道都查「派生量」（分值/统计/页面副本），**没一道查过推导它们的原始事实** |

> **第 14 类的可复用结论**：闸门容易围着**派生量**建（分值、统计、页面副本），
> 却漏掉**事实源头**——源错了，所有派生量都一致地错，于是每道闸门都显示「通过」。
> **加新闸门时问一句：这条事实是从哪来的？谁查过它的源头？**

逐轮细节见 `.workbuddy/memory/automations/3480cd21-*/memory.md`，此处只留**可复用**结论：

- **新数据入口的完整检查清单**（加一个入口必须同时问）：① 结构/必填 ② 枚举合法性 ③ 溯源存在性 ④ **页面级对应**（JSON 有 → 对应页面有吗）⑤ **副本/派生**（内嵌块、文档、派生列表）⑥ **回退法自证（正反两面）**。前 12 轮漏的几乎都是 ④⑤⑥。
- **拼写分裂（第十类·静默失效）**：两处写同一 JSON、页面读错拼那个 ⇒ 新条目同时失去徽章/筛选/统计，**而页面不报错、卡片照常渲染**。**凡两个脚本写同一个文件，先核对键名；同一概念不能有两种拼写。**
- **`docs/*.md` 是第五个漂移面**：纯文本，结构化闸门覆盖不到。**只审能自动判定的事实，不做全文数字正则扫描**——那类闸门 11 条里 9 条假阳性。**覆盖广但靠关键词打补丁的闸门，不如按定义能自动判定的窄口径。**
- **派生量不手写（第七类复发）**：顶层 `subjects` 漏一项 ⇒ 该科无筛选按钮。采集脚本**每个写入方都要现算**，只修数据层等于把漂移推迟到下次采集。**凡是「本次运行」概念的数据（增量、unchanged）就不该落盘。**
- **规范文档教人把纪律写反（第十一类）**：**「数据错了」只改一个条目，「教人写数据的文档错了」会持续产出错数据——修规范才改掉原因。** 判定口径必须**按结构**（表格列值、标题行）而非**按关键词全文匹配**。
- **范围确认**：`app/index.html` 用 localStorage、不读 `data/*.json`、设计如此，**不算漏网入口**。

**九条铁律**：

1. **「0 错误」可能只是没检查到。** 判据是「**该数据路径真的被检查到了**」，不是「校验通过了」。改完校验器要看它有没有立刻抓出存量违规；**抓不出才说明检查没生效**。**字段名错了等于没校验**——报错读不出定位信息＝把错误藏起来。
2. **闸门必须覆盖它声称覆盖的全部数据入口。** `check_tasks()` 曾只查 `data/wrong/`；`check_page_matches_data` 虽叫「页面 vs 数据层」却**只管试卷两页**。**命名/注释必须写明覆盖范围**。当前入口 6 个：`raw-manifest`·`wrong`·`exams`·`tasks`·`resources`·`data/README.md`，外加 `docs/*.md` 与**错题精讲页**。
3. **闸门上线前先跑一次看它报什么——自身假阳性会把真错误淹掉。** 已知四类：① `startswith` 匹配模块名，「I」命中「III」⇒ **整词相等**；② 筛选器哨兵值（`value=""`／「全部」）当枚举外值；③ 表格里把题号列「49-56」的 49/56 当实得候选 ⇒ **按列位置判定**；④ **把「尚未定论」误判成「已定论」**（第十四轮：`causePending: true` 的存疑题被要求填 `answerKey`，等于**逼人编造官方答案**）⇒ 判据要落在「是否已定论」这个**语义状态**上。
4. **「查了数据层」不等于「查了整个事实链」——副本同样会漂移。** 第七轮把 `count 17→21` 修进数据层，页面一个字节没变 ⇒ **少渲染 4 张卡片**，而 `meta.stats` 是死字段、页面上根本不显示。内嵌数据必须加**逐字节比对**闸门（`check_embedded_snapshots()`），且**修复要用数据层重新生成，不手工改数字**。
5. **同一事实散落 N 处，改一处就漏 N−1 处——要按「事实」建闸门，不是按「文件」建闸门。** 提示条写清楚了不等于正文清干净了。
6. **闸门自身的漏洞比没建闸门更危险——它会报「0 错误」，让人以为已经安全。** 同一形态反复出现：查「必填」二字而表头填 `| 是 |`；**豁免写成 `... or mnote`，而 got=null 的 gotNote 必然非空＝给所有违规发免死金牌**；`if a != b and a and b` 在 a 为空时短路。**只有回退法能暴露它们**，且**正反两面都要验**。定位数字时：**按所在块取窗口**，**正则要能看见 `<b>7</b> / 8` 这类夹标签写法**。
   > ⚠️ **回退法本身也会出事**：第十一轮用 `git checkout` 还原测试文件，**连带抹掉同文件里已完成的合法修复**。**注入前先 `cp` 备份、还原后逐字节比对 sha256**（`json.dump` 还会丢文件末尾换行）——别拿 git 恢复当撤销键。
7. **规范文档是数据入口的一部分，而且是最危险的那个。** 判定口径必须**按结构**而非**按关键词全文匹配**。**文档还要写明机器管不到什么**，否则下一个人会误以为已被守住。
8. **修掉一个实例不等于修掉这一类。** 纪律要落成**可自动判定的闸门**，不能只写成「某某要怎样」——否则换个对象就复发。
9. **闸门要覆盖事实源头，不能只覆盖派生量。** 分值/统计/页面副本都是派生量，源错了它们会一致地错、于是每道闸门都显示「通过」（第十四类）。加闸门时问：**这条事实从哪来？谁查过源头？**

### done ≠ 做完了

`status: done` 只说明**上一轮自认为**做完了。q5 页的 doneNote 写「五段范式齐备」，实际仍有 5 个真实空缺区块。

> **规程**：即使 `pending: 0` 也不要直接收工，先 grep `待补 ·` 确认真空缺。**判据是页面内容，不是队列状态。** doneNote 只写**亲自核实过**的事实。

**十四轮共踩了三种「假 done」，每种都比上一层更隐蔽**：
① HTML 有空缺（grep 抓得到）→ ② HTML 齐了但 JSON 空（**按定义 grep HTML 查不到**，这题在数据层等于不存在）→ ③ 两侧都有内容但「对不对」没人查（见闸门表第 13 类）→ ④ **源头事实本身无闸门**（第 14 类）。

> **规程**：交付错题内容是**三处**动作，缺一不可——① 填 HTML 空缺段；② **回写 `data/` 里对应 JSON 的同名字段**；③ **两侧内容符合五段范式**（`check_five_stage_paradigm()` 覆盖）。只做 ①② 属于「假 done」。

### 数据入库与字段坑

JSON · UTF-8 · 2 空格缩进 · 顶层带 `meta`（schema/created/count）· 分值 `full`/`lost` · 答案 `answerKey`+`childAnswer`（见答案字段纪律）· 每次入库 = 一次独立 commit。原图存 `RAW/`（已入 Git，事实依据层）。

- **错题 `id` 后缀不是题号**：`w-20261002-02` 是第几条记录。必须用 `qno` 或从标题抠「第N题」。
- **`sourceRaw` 可为数组**：多页试卷必然用数组，校验与生成都要兼容两种形态。
- **两份 JSON 结构不同**：`data/wrong/*.json` 顶层 `{meta, items}`；`data/exams/*.json` 顶层 `{meta, exams:[…]}`，逐题数据在 `exams[0].wrongs`。直接 `d['wrongs']` 会拿到空。
- **`data/resources/shanghai-papers.json` 不是孩子参加过的考试**，是公共试卷资源索引，**纪律上不进 `data/exams/`**。

## 自动化管道

**`tools/pipeline.sh` 是唯一入口**：ingest 原件 → 生成讲义骨架 → 校验数据 → commit + push。全部幂等，没变化不动 git。

### 脚本与 AI 的分工（硬边界）

脚本**只做确定性填充**，一律不做教学判断：解法步骤、断点分析、变式题、逐题判分、诊断结论全部标 `⚠️ 待补` 并登记到 `data/tasks/pending.json`，由 WorkBuddy 自动化「mySchoolBuddy 教学内容补全」（每 2 小时）补齐。

> 理由：解法步骤写错了比没有更危险。

### 生成器防覆盖

自动生成的页面头部带 `<meta name="generator" content="generated-by: tools/build_skeletons.py">`。

⚠️ **不能拿 generator 标记当「是不是人工页」的判据**——人工精修页往往仍带标记。真正的判据是**内容是否已实质填写**：exam 侧为含「失分在哪」段且「待补」≤4 次；wrong 侧为含「断点到底在哪」+「零跳跃分步讲解」且「待补 ·」≤1 次（`is_filled_wrong_page()`）。2026-10-03 用标记当判据时防护直接失效，又生成一份空壳。

**wrong 侧还必须管住「同名」情形**：主循环原先是 `if manual and basename(manual) != fn`——人工页恰在目标路径上时会被直接覆盖，且 `pending.json` 仍留着 done，看着一切正常。正确写法：`if manual:` 之后再判 `basename_differs or is_filled_wrong_page(text)` 才跳过。修完用 sha256 前后比对确认零覆盖。

**数空缺要区分占位与合法标记**：页头「分值待补」标签是合法状态标记（卷面无分值标注时的正确表达），不是空缺区块。数空缺用 `待补 ·`（带间隔号），**不要笼统 grep「待补」两个字**。

### 机器闸门

`tools/validate_schema.py` 是唯一执行者。**校验出错时照常提交、但拒绝推送**，并在 `data/_local/VALIDATION-FAILED.md` 留提醒。

| 纪律 | 机器检查什么 |
|---|---|
| 分值 | `full`/`lost` 为 null 必须 `scorePending: true`，反之亦然 |
| 溯源 | `sourceRaw`（字符串或数组）必须存在于 RAW/ 且已登记 manifest |
| 原件 | sha256 必须一致；不一致时比对 Git HEAD 区分「记录错」与「原件被改」 |
| got 依据 | 含存疑题或自述折算的模块 `got` 必须为 null（`check_module_got_grounded`） |
| 跨层一致 | **试卷**页 X/Y 与数据层逐模块比对（`check_page_matches_data`） |
| 五段范式 | **错题**精讲页：变式三类配比 / 简单变式须真有数值变化 / 想五题末题须为「何时失效」/ steps 须有断点 / 每步三件套 / HTML 标题与 JSON 逐条对应（`check_five_stage_paradigm`） |

**新增任何数据入口时，同步在 `main()` 里加对应 check。** 当前 `main()` 顺序：`check_wrong` → `check_exams` → `check_tasks` → `check_resources` → `check_cause_enum` → `check_embedded_snapshots` → `check_no_fabricated_score` → `check_module_got_grounded` → `check_page_matches_data` → `check_five_stage_paradigm` → `check_papers_derived` → `check_doc_numbers` → `check_data_readme`。

> ⚠️ **命名会误导**：两个 `check_page_*` 各管一半（前者只管试卷页、后者只管错题页）。新增页面类闸门时，**在 docstring 第一行写清覆盖哪些页面**。
