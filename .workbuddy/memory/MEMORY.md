# mySchoolBuddy · 项目约定

## 交付标准

**讲题类内容一律出单文件 HTML，不要用聊天文字讲题。**

> 2026-10-02 用户反馈——"文字讲题是我看得清，不是他看得清"。

聊天文字适合我讲清楚，不适合孩子读进去。孩子的认知负荷要靠**分层、渐进、图形、可交互**降低，纯文本做不到。

### 五段范式（硬性标准）

用户要求固定范式："**练一题，看三题，想五题**"。已建 skill `wrong-question-coaching`。

```
① 原题 → ② 拆解 → ③ 零跳跃讲解 → ④ 三题变式 → ⑤ 迁移想五题
```

| 段 | 硬性要求 |
|---|---|
| ① 原题 | **必须置顶**。题干逐字全文（定义句/括号补充/问法一字不省）+ 限定词 `<span class="hl">` 高亮 + 原卷照片（题干裁切+整题，折叠）+ 题干拆解表 |
| ② 拆解 | 表格逐句翻译成数学条件，**收尾点明"最容易漏的是第几条"** |
| ③ 零跳跃讲解 | 一步一个动作，渐进展开，★ 标断点。**每步三件套：动作/依据/检验**。舍根与分类讨论单列。末尾逐个原始条件验证 |
| ④ 三题变式 | **固定配比**：简单变式（只改一个数值）+ 同类型（换考点同手法）+ **问答对调（已知与所求互换）**。答案全 `<details>` 折叠 |
| ⑤ 迁移想五题 | 抽掉脚手架。3-5 个递进问题，填空+即时判题。**必含"什么情况下这方法失效"** |

**总时长 25-35 分钟**，超过就是题海。**问答对调不可省**——很多孩子是"记住套路"不是"真懂"，只有对调才能测出来。

**文科适配**（语文/英语/历史/政治/地理）：骨架不变。②改为标注答案在第几段+材料层次；③改为**逐句解读文本**（定义句/条件句/**答案句**/干扰句）+ 答题模板拆解；④改为换材料/换设问（概括→原因→评价→启示）；⑤改为题型识别+答题角度转换。

### 单文件 HTML 规格

| 项 | 要求 |
|---|---|
| 结构 | 单个 `.html`，内联 CSS/JS，零外部依赖 |
| 宽度 | 正文 max-width 780px 居中 |
| 视觉 | 浅色 Stripe 风格 + 钛金灰 `#1C1C1E`/`#A1A1AA` + 暖金 `#F59E0B` |
| 字体 | 16px 基准（移动端 15.5px），行高 1.75，断点 600px |
| 命名 | `docs/实战表/学科/题号-主题-精讲.html` |
| 模板 | 专家包内 `skills/wrong-question-coaching/assets/template.html`（含 `{{}}` 占位） |

**图像资源**：原图归档 `data/_scans/YYYY-MM-DD/`，**该目录会被清空**（含个人信息不入 Git）。建议同时存题干裁切图（`sips -c 高 宽 --cropOffset y x`）+ 整题图。页面用相对路径引用。**交付前必须用真实浏览器验证 `img.naturalWidth > 0`**。

**其他必备结构**：图形先行 → 已做对的部分（先建信心）→ 断点定位（说清错值怎么来的）→ 分步法 → 坑的形态对照表 → 检验题 2 道（答案折叠，用户讨厌剧透）→ 复述检验 → 家长区（深色卡片，具体到分钟）。

**交互约定**：渐进解锁（未完成上一步则下一步 `locked`）· `localStorage` 进度持久化（key `msb.<题目>.progress.v1`）· 即时判题（关键词宽松匹配，答错只提示不给答案）· `<details>` 折叠答案 · 代码块复制按钮 · 重置需 `confirm`。

## 数据纪律

### 错因判定纪律

**仅凭最终答案判错因会误判。必须回看中间步骤。**

2026-10-02 q19 教训：最终答案错，但中间列出的方程完全正确。仅看答案会判成「概念不清」（错），回看步骤才看出是「方法没想到」（对）。二者救法完全相反——概念不清要回教材重读概念，方法没想到要归类题型+练固定动作。混淆会导致无效刷题。

录入错题**必须附中间步骤判读**。

### 分值纪律

**照片上没有分值标注就留 `null` + `scorePending: true`，绝不估算。** 缺分值不能计入失分热区统计。

- **反向也成立**：卷面**明确标了**单题分值（如 V-D「第 57-60 题每题 2 分」）就要**回填**，留 null 是失职。判据是「照片上有没有」，不是「推算得出来吗」。
- **算不出合计就不给合计**。分项里有一处得分不明就别写「已确认实得 X 分」——无依据的合计数字比没有更糟，它会被当成结论引用。

### cause 字段纪律

**`cause` 只能是五类枚举之一**（概念不清/方法没想到/计算失误/审题错误/表达不规范），长描述放 `causeNote`。**只能选一个主因**，副因放 `causeSecondary`。存疑用 `causePending: true`，不硬归类。

> 教训：`cause` 被塞「审题错误 + 补数漏步」这类长句，校验器 8 条警告，五类统计全部漏掉——**看起来有数据，实际统计不出来**。

错因五类在仓库里有 **7 处定义**，靠人记必分叉。**定义源是 `docs/方法论/错因分类与复习排期.md` 的表格**，其余六处必须逐字一致：`validate_schema.py` 的 `CAUSES` · `app/index.html` 的 `#w-cause` · `#f-cause` · **`const ci`（错因 chip 着色，缺项静默退化默认灰 `c0`，肉眼核验通不出错）** · `README.md` schema 示例 · `build_skeletons.py` 的 `CAUSE_TONE`。

机器闸门 `check_cause_enum()` 已做七处比对。**第五类是「表达不规范」，不是「时间不够」**——后者是条件不是病因（考试做不完的真因通常是「卡壳不会跳过」，归 `方法没想到`，救法加限时套卷）。

### 核卷纪律

**判分前必须放大原卷，不能看缩略图下判断。误判比漏判更危险。**

```bash
sips -c 高 宽 --cropOffset y x 原图.jpg --out /tmp/x.jpg   # 裁切
sips -Z 2000 /tmp/x.jpg --out /tmp/x-big.jpg                # 放大后再看
```

两次教训：① p3 缩略图上第 46 题的红笔 × 看着像判错，放大后确认是**划掉三个干扰项**、选 D 正确。② 光标下**一条长斜线 ≠ 逐题批改**——IV 大题 36/37 题下方看着各有红笔，放大追踪笔画后确认是老师一次性拉的长斜线，两题均无单独 √，差点被缩略图洗掉一处存疑失分。

### 跨层一致性纪律

**同一事实在数据层与所有页面必须一致。发现打架时不要选边站，要回到原卷裁决。**

> **裁决原则**：两侧冲突时，正确解不是挑一个信，而是**找出「两边都缺依据」的那个共同前提**，显式记成 null。

实例：`modules[I 听力].got=25`（满分）却在同一行 evidence 写「11 仅错 1 空」且 wrongs 里有第 11 题；同时《试卷拆解》写 25/25、《整卷分析》写 24/25。裁决：卷面听力 C 只标「10 分」共 5 空、无单空分值，24 与 25 **都是 10÷5 等分折算，两个都不能用** → `got` 留 **null** + `gotNote` 写明理由，两份页面同步不给具体实得。

### ⚠️ 闸门纪律（五条，本项目九轮反复踩坑的核心）

本项目已连犯**十类「0 错误也抓不到」的缺陷**，每类都是新的盲区：

| # | 缺陷 | 为什么抓不到 |
|---|---|---|
| 1 | HTML 有 `待补 ·` 空缺 | grep 能抓到 |
| 2 | 校验器漏 `exam.wrongs` | 0 错误是假象 |
| 3 | 字段名错成 `no`（实为 `qno`） | 报错显示「第?题」＝把错误藏起来 |
| 4 | HTML 齐了但 JSON 空 | 按定义 grep HTML 查不到 |
| 5 | 模块 got 与本模块失分题矛盾 + 跨页面数字打架 | 单看任一处都「像对的」 |
| 6 | 闸门只覆盖了一半数据入口 | 只验一侧＝半个闸门 |
| 7 | 手工统计数字漂移（`data/resources/` 从未被校验） | 增量与总量混用，单看都像对的 |
| 8 | 页面内嵌副本与数据层漂移（试卷地图页的 `const DATA`） | 闸门全作用于「磁盘上的 JSON」，漂移发生在「JSON 被拷进 HTML 之后」——按定义 grep JSON 查不到 |
| 9 | 跨页修订的漏网残留（提示条宣布作废、正文仍引用） | 「散文数字」既不在 JSON 也不在 `const` 块，前八道闸门一道都覆盖它 |
| 10 | **同一概念两套拼写 + `docs/*.md` 是第五个漂移面 + 派生量手写** | 见下 |

**第十类详解（2026-10-03 第十轮）**：

- **拼写分裂**：`trusthLevel`（Level 前多一个 h，索引 21 条全是它）vs `trustLevel`。两个采集脚本写**同一个 JSON**，页面读错拼那个。跑一次 zujuan 采集 ⇒ 新条目同时失去存疑徽章、筛选与统计，**而页面不报错、卡片照常渲染**。值域同时分叉（`high/medium/unverified/suspect` vs 脚本里的 `"B"`）。凡两个脚本写同一个文件，先核对键名。
- **`docs/*.md` 是第五个漂移面**：纯文本，前九轮的结构化比对闸门一道都覆盖不到。上海试卷采集页科目表合计 17 而 `count=21`（漏全科 3 + 跨学科 1）。已加 `check_doc_numbers()`，**只审能自动判定的事实**（合计恒等、计数比对），**不做全文数字正则扫描**——覆盖广但靠关键词打补丁的闸门 11 条里 9 条是假阳性。
- **派生量不手写**（第七类复发）：顶层 `subjects` 漏「道德与法治」，页面统计条正是读它 ⇒ 科目数少算 1、该科无筛选按钮。`scan_zujuan_papers.py` 此前只重算 `count`/`stats`，**采集一次就重新漂移** ⇒ 派生量必须在**每个写入方**都现算。

**由此沉淀的五条铁律**：

1. **「0 错误」可能只是没检查到。** 判据不是「校验通过了」，而是「**该数据路径真的被检查到了**」。改完校验器要看它有没有立刻抓出存量违规——抓不出才说明检查没生效。**新增数据入口时必须同步加对应检查**，否则新数据等于无约束。
2. **闸门必须覆盖它声称覆盖的全部数据入口。** `check_tasks()` 曾只查 `data/wrong/`，exam 任务因 id 前缀不匹配被 `continue` 跳过。**回退法自证时 wrong 与 exam 必须各做一次**。当前已覆盖 5 个入口：`data/raw-manifest` · `data/wrong` · `data/exams` · `data/tasks` · `data/resources`；`docs/*.md` 由 `check_doc_numbers()` 按「可自动判定的事实」覆盖。
3. **闸门上线前先跑一次看它报什么——自身假阳性会把真错误淹掉。** 已知两类假阳性：① 用 `startswith` 匹配模块名，「I」命中「III」、「II」也命中「III」，凭空多报 2 条，必须**整词相等**；② 把筛选器的哨兵值（`value=""`／文本「全部」）当枚举外值误报，必须先剔除。
4. **「查了数据层」不等于「查了整个事实链」——副本同样会漂移。** 前七轮的闸门全部读磁盘上的 JSON，页面里**手工拷贝**的那份从此各活各的。第七轮把 `count 17→21`、`fetched 0→11` 修进数据层，页面一个字节没跟着变 ⇒ **少渲染 4 张试卷卡片**，而 `meta.stats` 是死字段、页面上根本不显示，**统计数字错了反而没人看得见**。凡页面内嵌了数据，必须加**逐字节比对**闸门（`check_embedded_snapshots()`），且**修复要用数据层重新生成，不手工改数字**。
5. **同一事实散落 N 处，改一处就漏 N−1 处——要按「事实」建闸门，不是按「文件」建闸门。** 提示条写清楚了不等于正文清干净了；**同一个键名也不能有两种拼写**。派生量必须现算，且**每个写入方都要算**——只修数据层等于把漂移推迟到下次采集。
   > 第九轮据此加 `check_no_fabricated_score()`：只审**数据层 `got` 为 null 的模块**（纪律已判定「无卷面依据」的那些），页面若在这些模块上写 X/Y 即报错；合法引用须在**同一句**内写明为何不折算。踩坑两次：① 首版扫全站 `X/Y`，11 条里 **9 条是假阳性**（数学比例、选择项、题号、样板页基线）——**覆盖广但靠关键词打补丁的闸门，不如按定义能自动判定的窄口径**；② 窗口开 300 字符时，**上一条 `<li>` 的免责说明替下一条豁免**，闸门失灵却报 0 错误——边界必须对齐到句读。


**派生量原则**：能被算出来的数字**不要手写**。`data/resources/shanghai-papers.json` 的 `meta.stats` 原本是「本次运行增量」，落盘即失真（下次运行就变），与累积的 `meta.count` 必然对不上。已改为由 `papers` 数组现算，三项之和恒等于 `count`。**凡是「本次运行」概念的数据（增量、unchanged），就不该落盘。**

**字段名错了等于没校验**：报错信息里读不出定位信息，等于把错误藏起来。

### done ≠ 做完了

`pending.json` 里 `status: done` 只说明**上一轮自认为**做完了。q5 精讲页的 doneNote 写「五段范式齐备」，实际仍有 5 个真实空缺区块——记录与事实不符，队列显示 pending: 0 却什么都没交付。

> **规程**：即使 `pending: 0` 也不要直接收工，先 grep `待补 ·` 确认真空缺。**判据是页面内容，不是队列状态。** 写 doneNote 只写**亲自核实过**的事实。

**HTML 写完了 ≠ 数据层写完了**（更隐蔽）。q19 曾在 HTML 里五段齐备，但 JSON 的 `steps`/`variants`/`thinkQuestions` 一个都没有——而 `build_skeletons.py` 与一切数据分析读的都是 JSON，**HTML 有内容 + JSON 空 = 这题在数据层根本不存在**。

> **规程**：交付错题内容是**两处**动作，缺一不可——① 填 HTML 空缺段；② **回写 `data/` 里对应 JSON 的同名字段**。只做 ① 属于「假 done」。

### 数据入库

JSON · UTF-8 · 2 空格缩进 · 顶层带 `meta`（schema/created/count）· 分值字段 `full`/`lost` · 对比字段 `answerKey`（正确答案）+`childAnswer`（孩子原答案）· 每次入库 = 一次独立 commit。

原图存 `RAW/`（已入 Git，是事实依据层）。**页面必须引 `RAW/`，不要引 `data/_scans/`**（已 gitignore，远端必断链）。

### 数据字段坑

- **错题 `id` 后缀不是题号**：`w-20261002-02` 是第几条记录。必须用 `qno` 字段或从标题抠「第N题」，否则会生成 `q1-…` 而卷面写的是 q19。
- **`sourceRaw` 可为数组**：多页试卷必然用数组，校验与生成都要兼容两种形态。
- **两份 JSON 结构不同**：`data/wrong/*.json` 顶层 `{meta, items}`；`data/exams/*.json` 顶层 `{meta, exams:[…]}`，逐题数据在 `exams[0].wrongs`。直接 `d['wrongs']` 会拿到空。
- **`data/resources/shanghai-papers.json` 不是孩子参加过的考试**，是公共试卷资源索引，**纪律上不进 `data/exams/`**。

## 自动化管道

**`tools/pipeline.sh` 是唯一入口**：ingest 原件 → 生成讲义骨架 → 校验数据 → commit + push。全部幂等，没变化不动 git。

### 脚本与 AI 的分工（硬边界）

脚本**只做确定性填充**，一律不做教学判断：解法步骤、断点分析、变式题、逐题判分、诊断结论全部标 `⚠️ 待补` 并登记到 `data/tasks/pending.json`，由 WorkBuddy 自动化「mySchoolBuddy 教学内容补全」（每 2 小时）补齐。

> 理由：解法步骤写错了比没有更危险。

### 生成器防覆盖

自动生成的页面头部带 `<meta name="generator" content="generated-by: tools/build_skeletons.py">`。

⚠️ **不能拿这个标记当「是不是人工页」的判据**——人工精修页往往仍带标记（脚本生成骨架后被逐字改出来的，如 q5 与英语拆解页）。真正的判据是**内容是否已实质填写**：exam 侧为含「失分在哪」段且「待补」≤4 次；wrong 侧为含「断点到底在哪」+「零跳跃分步讲解」且「待补 ·」≤1 次（`is_filled_wrong_page()`）。2026-10-03 用标记当判据时防护直接失效，又生成一份空壳。

**wrong 侧还必须管住「同名」情形**：主循环原先是 `if manual and basename(manual) != fn`——人工页恰在目标路径上时会被直接覆盖，且 `pending.json` 仍留着 done，看着一切正常。正确写法：`if manual:` 之后再判 `basename_differs or is_filled_wrong_page(text)` 才跳过。修完用 sha256 前后比对确认零覆盖。

**数空缺要区分占位与合法标记**：页头「分值待补」标签是合法状态标记（卷面无分值标注时的正确表达），不是空缺区块。数空缺用 `待补 ·`（带间隔号）这个占位块特征串，或直接数 `⚠️ 待补` 块，**不要笼统 grep「待补」两个字**。

> **空壳页比没有页面更糟**：它看起来是有效交付物，实际是空数据，且每次跑管道都会新开一份。根因是脚本按 `name` 造文件名、人工页用纯日期命名，两者永远对不上。

### 三条硬纪律的机器闸门

`tools/validate_schema.py` 是唯一执行者。**校验出错时照常提交、但拒绝推送**，并在 `data/_local/VALIDATION-FAILED.md` 留提醒——问题必须让人看见。

| 纪律 | 机器检查什么 |
|---|---|
| 分值 | `full`/`lost` 为 null 必须 `scorePending: true`，反之亦然 |
| 溯源 | `sourceRaw`（字符串或数组）必须存在于 RAW/ 且已登记 manifest |
| 原件 | sha256 必须一致；不一致时比对 Git HEAD 区分「记录错」与「原件被改」，后者拒绝自动修复 |

**新增任何数据入口时，同步在 `main()` 里加对应 check。**

## 定时任务

launchd plist 在 `tools/launchd/com.myschoolbuddy.pipeline.plist.template`，用 `__REPO__` 占位绝对路径。触发器两套缺一不可：**WatchPaths**（目录变化即跑）+ **StartInterval 1800**（休眠兜底）。

> ⚠️ 本 IDE/沙箱内 shell 无法向 launchd 注册服务（error 5），且 `launchctl load` 会**返回成功但实际没注册**——必须用 `launchctl print` 确认。安装走 `tools/install-launchd.sh install`。
