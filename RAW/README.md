# RAW/ · 原件层

> **这里是唯一的事实来源。** 所有分析结论都从这里派生，原件在，结论就可复现、可核对、可推翻。

---

## 核心原则：不可变事实层

RAW 里的文件一经入库**不再修改**。它们是证据，不是工作稿。

这条纪律解决一个具体问题：三个月后孩子说"这道题我没错过"，或者分析结论被发现算错了——如果原件还在，翻出来一看就知道真相；如果只有一份改过的 JSON，谁也说不清。

| 允许 | 禁止 |
|---|---|
| 新增原件 | 修改已入库的原件内容 |
| 重命名（保持命名规范） | 覆盖已入库的文件 |
| 在 `_originals/` 保留手机原图 | 删除原件（除非明确判断为误拍） |
| 补拍漏页（文件名加 `-p2`） | 裁剪掉卷面边缘的题目 |

**派生层随时可重建，原件层不可再生。** 这就是两者的分工。

## 目录结构

```
RAW/
├── 试卷/           # 整卷照片/PDF：期中考、月考、单元测、模拟考
├── 错题照片/       # 单题特写：从整卷里裁出来的某道错题
├── 试卷答案/       # 官方答案、老师批改版、家长讲评稿
├── 其他材料/       # 讲义、练习卷、错题本照片、通知等
└── _originals/     # 手机原图自动备份（.gitignore 排除，不入库）
```

`_originals/` 是入库脚本自动创建的，存放压缩前的 HEIC/PNG 原图。**不入库**（体积大），但本地保留，必要时可重新处理。

## 命名规范

```
日期-类型-科目-说明.扩展名

20260928-期末-数学.jpg
20261005-月考-物理.pdf
20260928-数学-第18题.jpg
20260928-数学-答案.pdf
```

| 字段 | 说明 | 示例 |
|---|---|---|
| 日期 | 考试日期，8 位数字。**用考试日期，不是拍照日期** | `20260928` |
| 类型 | 期末/月考/单元测/模拟/期中 | `期末` |
| 科目 | 数学/物理/化学/英语/语文/道法 | `数学` |
| 说明 | 题号、页码、特殊标记 | `第18题`、`p2` |

**多页试卷**：`-p1` `-p2` `-p3` 顺序编号。

```
20260928-期末-数学-p1.jpg
20260928-期末-数学-p2.jpg
```

**同一份材料的后续版本**（如订正版、补充卷）：加 `-v2`，不要覆盖原文件。

## 入库流程

```bash
# 1. 把手机拍的卷子、下载的 PDF 放进对应子目录，命名按上面的规范
cp ~/Downloads/IMG_1234.HEIC "RAW/试卷/20260928-期末-数学-p1.HEIC"

# 2. 预处理入库（压缩 + 建索引）
tools/ingest-raw.sh --dry-run    # 先看会做什么
tools/ingest-raw.sh              # 确认无误再执行

# 3. 提交
git add RAW data/raw-manifest.json && git commit -m "raw: 20260928 期末数学卷入库"
```

### 脚本做了什么

| 操作 | 说明 |
|---|---|
| 图片压缩 | JPEG、长边 2000px、质量 q=50 |
| 原图备份 | HEIC/PNG 原图移入 `_originals/`（不入库） |
| PDF 处理 | 原样入库，不做有损压缩；超 10MB 给出警告 |
| 建索引 | 写入 `data/raw-manifest.json`，含 sha256 |
| 幂等 | 已入库文件自动跳过，`--force` 可强制重做 |

**为什么 q=50 就够**：试卷是白底黑字的高对比内容，JPEG 在这种素材上效率很高。实测 3024×4032 的手机原图 10.5MB → 305KB（降幅 97%），文字完全清晰可读。q=80 反而到 704KB，对这个场景是浪费。

**长边为什么限 2000px**：A4 试卷在 2000px 长边下，正文文字仍有约 150-180 像素高，缩放查看绰绰有余。再高只是浪费仓库空间。

## 拆解映射：原件 → 派生层

这是你提的核心诉求——**卷子上的错题放到错题里，整卷结构分析放到结构分析里**。映射关系如下：

```
RAW/试卷/20260928-期末-数学-p1.jpg          ← 整卷原件（不可变）
        │
        ├── 逐题挑出错题 ──────────→ data/wrong/wrong-20260928-math.json
        │                              sourceRaw: "RAW/试卷/20260928-期末-数学-p1.jpg"
        │                              每条错题记：题号、模块、知识点、满分、实失、错因
        │
        ├── 卷面结构分析 ───────────→ data/exams/2026-09-28-期末数学.json
        │                              sourceRaw: 同上
        │                              记录：卷面分值结构、模块划分、各模块得分率
        │
        └── 单题特写（可选）────────→ RAW/错题照片/20260928-数学-第18题.jpg
                                       错题复杂/需要看清步骤时补拍
```

| 原件类型 | 拆解去向 | 产物 schema |
|---|---|---|
| 整卷照片/PDF | 逐题错题 | `wrong.v1` |
| 整卷照片/PDF | 卷面结构分析 | `exam.v1` |
| 错题照片 | 单题详情 | `wrong.v1`（sourceRaw 指向错题照片） |
| 试卷答案 | 错因判定依据 | 用于核对 `cause` 字段是否判对 |
| 其他材料 | 视内容 | 讲义 → 可能拆出练习题 |

**双向可溯**：`data/raw-manifest.json` 里每条原件都有 `parsed.wrongIds` 和 `parsed.modules`，反向记录"这份原件解析出了什么"。原件 ↔ 结论之间没有断链。

## manifest 字段说明

`data/raw-manifest.json`：

```json
{
  "meta": { "schema": "raw.v1", "created": "2026-10-02", "updated": "..." },
  "items": [
    {
      "file": "RAW/试卷/20260928-期末-数学-p1.jpg",
      "kind": "image",
      "bytes": 312598,
      "sha256": "0e51813b...",
      "width": 1500,
      "height": 2000,
      "originalBytes": 10987649,
      "status": "已入库·待解析",
      "parsed": { "wrongIds": [], "modules": [] }
    }
  ]
}
```

| 字段 | 作用 |
|---|---|
| `sha256` | 内容指纹。文件被改动后指纹变化，可检测原件是否被动过 |
| `originalBytes` | 压缩前体积，用于评估压缩效果 |
| `status` | `已入库·待解析` → `已解析` |
| `parsed` | 解析产物反向索引，填入对应错题 ID 和模块名 |

## 常见问题

**Q：可以用微信/QQ 收到的图片直接放吗？**
可以。`ingest-raw.sh` 会统一转成 JPEG 并压缩，格式不用管。但建议先按命名规范改好文件名，否则 manifest 里的路径会很难看。

**Q：拍糊了怎么办？**
重拍，用新文件名（加 `-v2`），旧的删掉。**不要**试图用图像增强修复代替重拍——原件的价值在于它是真实拍摄，修复过的图像不能作为证据。

**Q：PDF 里的试卷怎么拆？**
PDF 原样存进 RAW/试卷/，解析时按页拆。整个 PDF 作为一份原件，manifest 里记 `kind: "pdf"`。

**Q：一定要立刻入库吗？**
不是。但**建议考试当天就存**，因为记忆会模糊，题干细节记不清会导致后面解析时归因错误。原始照片比你的记忆可靠。
