# mySchoolBuddy · 中学生学习助手

> 一个孩子 + 一位老教师（AI 形态）的错题与失分点作战室。
> 目标不是"题库机器"，而是把**失分结构**看清楚：分数丢在哪、为什么丢、下一周先补哪块。

上海某初三学生（2027 届 / 上海新教材第一届中考）长期跟踪项目。

---

## 这个仓库解决什么问题

孩子的现状诊断已经很清楚：**没有偏科，问题在于"会做的题在丢分"**。
语数英三科占全卷失分的 81%，而这些失分并不是不会，而是**概念不清、方法没想到、计算失误、审题错误、表达不规范**这五类原因造成的（口径见 [docs/方法论/错因分类与复习排期.md](docs/方法论/错因分类与复习排期.md)）。

所以本仓库的核心资产不是题目，而是**每一分丢在哪、属于哪一类病因**。

| 痛点 | 本仓库的解法 |
|---|---|
| 错题本只记题目，不记分数 | 错题 = 失分点，绑定分值与来源试卷 |
| 刷题很多，不知道哪块在崩 | 失分点热区图：按模块/知识点/病因排序 |
| 同一类题反复错 | 错因归类 + 复测排期，错了必须回炉 |
| 学了一堆，不知道补完没有 | 知识点掌握度表，变化可见 |
| **结论对不上原始卷子，没法核对** | **RAW 原件层 + sha256 指纹，证据永久可溯** |

│   └── launchd/              #   定时任务 plist 模板

**四层为什么要这样分**

| 层 | 性质 | 变更频率 | 为什么独立 |
|---|---|---|---|
| `RAW/` | **不可变事实** | 只增不改 | 原件是证据。丢了就无法复现和核对任何结论 |
| `data/` | **结构化事实** | 每次考试后更新 | Git 擅长记录变化，答案在 diff 里 |
| `docs/` | **判断与方案** | 诊断后产出 | 事实与结论分层，避免「我觉得他数学差」和「他数学丢了 27 分」混为一谈 |
| `app/` | **工具** | 频繁改动 | 改代码不该搅动文档 diff |

**核心数据流**

```
拍照 / PDF → RAW/（原件，压存入库，sha256 指纹）
                 ↓ 对照原件拆解
             data/wrong/     逐题错题（含满分、实失、错因）
             data/exams/     卷面结构分析（模块得分率）
                 ↓ 统计
             失分点热区 → docs/实战表/（8 周作战方案）
                 ↓ 执行
             data/progress/（复测记录）→ 验证热区是否收敛
```

**双向可溯**：`raw-manifest.json` 每条原件都记录 `parsed.wrongIds` 与 `parsed.modules`，反向索引到解析产物。原件与结论之间没有断链。

## 快速开始

### 1. 存一份新卷子

```bash
# 把手机拍的卷子放进 RAW/试卷/，按规范命名
cp ~/Downloads/IMG_1234.HEIC "RAW/试卷/20260928-期末-数学-p1.HEIC"

tools/ingest-raw.sh --dry-run    # 预演：会压缩成什么样
tools/ingest-raw.sh              # 执行：压缩 + 建索引

git add RAW data/raw-manifest.json && git commit -m "raw: 20260928 期末数学卷入库"
```

脚本实测：手机原图 10.5MB → 305KB（降幅 97%），长边 2000px，文字完全可读。
命名规范与拆解映射详见 `RAW/README.md`。

### 2. 拆解成数据

对照 `RAW/` 里的原件，把错题和卷面结构填进 `data/wrong/` 与 `data/exams/`，schema 见 `data/README.md`。

> **每条错题必须记 `full`（满分）和 `lost`（实失）** —— 缺这两个字段只能做题数统计，做不了失分点分析。
>
> ⚠️ 但**键必须在、值可以为 `null`**：照片上没有分值标注就是没有，
> 此时写 `null` + `scorePending: true`，**绝不估算**。完整口径见 `data/README.md` 的「分值纪律」。

### 3. 用应用

浏览器直接打开 `app/index.html`。零依赖、零构建、数据存 localStorage，支持 JSON 导入导出。

> 注：应用是**独立工具**，用 localStorage 存自己的数据，**不读 `data/*.json`**（设计如此，不是漏网入口）。它与 `data/` 的 v1 schema 尚未打通，升级计划见下方「待办」。

### 4. 写一份实战表

参照 `docs/实战表/数学/样板-数学二次函数专项.html` 的结构（诊断 → 分型 → 高频失分 → 8 周节奏 → 家长动作），新表放对应学科目录，文件名格式 `主题-学科-专项.html`。编写标准见 `docs/实战表/README.md`。

> **错题精讲页**另有一套更严的标准（五段范式：原题 → 拆解 → 零跳跃讲解 → 三题变式 → 迁移想五题），
> 由 `tools/validate_schema.py` 的 `check_five_stage_paradigm()` 机器校验。
> 整卷的深度诊断走 `docs/整卷分析/`，**人工写，生成器不碰**。

### 5. `docs/实战表/` 与 `docs/整卷分析/` 的分工

同一份卷子可能同时有两个页面，**这不是重复，是两个视角**：

| | `docs/实战表/<学科>/…-试卷拆解.html` | `docs/整卷分析/…-整卷分析.html` |
|---|---|---|
| **谁写** | `tools/build_skeletons.py` 生成骨架，AI 补全教学内容 | **纯人工**，生成器不写这个目录 |
| **视角** | 失分结构速览：分模块得分率 + 诊断结论 + 优先级 | 深度诊断：逐条失分解剖 + 洞察 + 家长执行区 |
| **给谁看** | 孩子，按优先级刷 | 家长，判断方向对不对 |
| **更新时机** | 每次新卷入库自动重生成 | 人工判断后手动写 |
| **闸门** | `check_page_matches_data` + `check_five_stage_paradigm` | `check_page_matches_data` |

现存一对：`docs/实战表/英语/2026-10-02-单元测-试卷拆解.html`（30K）与
`docs/整卷分析/2026-10-02-英语Unit1A-整卷分析.html`（38K），同 `examId: e-20261002-01`。

**判据**：要「按优先级刷题」看前者，要「这一阶段该怎么打」看后者。**两者引用的分数必须同源**——
若两者对不上，回原卷裁决，不要各自选边站。

## 数据模型

错题对象用 schema `wrong.v1`，**37 个字段**。核心分组（完整定义见 `data/README.md`，那是规范源）：

```json
{
  "id": "w-20261002-01", "qno": 19, "subject": "数学", "module": "二次函数",
  "sourceRaw": ["RAW/试卷/20261002-单元测-数学-p2.jpg"],
  "full": null, "lost": null, "scorePending": true,
  "answerKey": "(3, −4)", "answerKeySource": "教材例题", "childAnswer": "(6, −3)",
  "stem": "题干逐字全文…", "breakdown": [["原句", "翻译成条件"]], "breakdownKey": 3,
  "doneRight": [["他写下的", "为什么对"]], "doneWrong": [["他做错的", "错在哪一步"]],
  "cause": "概念不清 | 方法没想到 | 计算失误 | 审题错误 | 表达不规范",
  "causeNote": "中间方程全对，方法没想到",
  "causeSecondary": "计算失误", "causePending": false,
  "steps": [{ "action": "…", "basis": "…", "check": "…", "breakpoint": true }],
  "variants": [], "thinkQuestions": [], "reviewRounds": []
}
```

> 上面的 `cause` 行是**枚举清单**（错因五类的完整定义，规范源是 `docs/方法论/错因分类与复习排期.md`），
> 单条错题实际只填其中一个值。**第五类是「表达不规范」不是「时间不够」**——
> 后者是条件不是病因（做不完的真因通常是「卡壳不会跳过」，归「方法没想到」）。
>
> `causePending: true` 表示病因**尚未判出**，此时 `cause` **必须为空**，只留 `causeNote` 写明为什么定不了。
> 「粗心。」这类没指向任何步骤的套话**非法**——它无法区分「方法没想到」与「概念不清」，而这两者救法完全相反。

三条最容易踩的：

| 纪律 | 说明 |
|---|---|
| **分值必须有键，值可为 null** | 照片上没印分值就 `null` + `scorePending: true`，**绝不估算**；反过来卷面印了就必须回填 |
| **答案错了整套判断全反** | `answerKey` 决定「断点在哪」才成立，`childAnswer` 决定「已做对」能写什么 |
| **只记 ✓ 不记 ✗ ⇒ 断点从证据退化成推断** | `doneWrong` 是断点的直接证据，必须逐项对照原卷手写 |

`exams/*.json` 用 schema `exam.v1`，顶层 `{meta, exams:[…]}`，逐题失分在 `exams[0].wrongs`，卷层主键叫 `id` 不叫 `examId`。

## Git 约定

- `main` 为稳定分支，功能开发走分支
- `data/` 与 `RAW/` 下的文件用 JSON / JPEG，**明文可读，diff 友好**
- `RAW/` 入库与 `data/` 解析分开提交：一次考试 = 两条 commit（先 raw 后 data）
- 每次实战表新增 = 一次独立 commit，便于回溯"哪张表对应哪次诊断"
- 仓库含孩子个人信息，**保持私有**

## 免责与边界

- 教材版本相关内容以**孩子手上那本课本目录**为准，版本会修订。
